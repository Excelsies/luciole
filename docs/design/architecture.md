# Architecture and ownership

## Dialog lifetime

[PageContext](../../src/app/page/page_context.h) chooses each popup's dismissal through `PopupDismiss`. Menus, popovers and dialogs opened with `OutsideClick` keep normal Wayland grabs and outside-click dismissal. Dialogs opened with `Explicit` (the default for forms) retain their scene, focus and drafts across application-window focus changes, using the existing popup transport without an explicit grab. [BrowserPage](../../src/app/page/browser_page.cpp) consumes dialog-background clicks, restores its text-input context on focus return, and keeps all explicit teardown in ActivePopup. Dialog dropdowns are grabbing child popups of the dialog. KWin and Hyprland move keyboard focus to a grabbing popup, so the parent window's focus loss is not a reason to close the dropdown; the compositor dismisses it when focus moves to another client, and that dismissal is always honored. This is application policy, not a change to the mirrored rendering library.

[WorkspaceApplication](../../src/app/workspace_application.cpp) dims the parent client area behind modal dialogs using one shared Noctalia Box per window. The backdrop uses the palette's Scrim role at half opacity, covers all window content including split panes, and has no input target. Dialogs remain on their own child surfaces above it. [BrowserPage](../../src/app/page/browser_page.cpp) uses the existing Explicit dismissal policy to identify modal dialogs. Quick preview, an outside-click dialog, is dimmed too; other outside-click dialogs such as shortcut help retain an undimmed parent alongside menus and popovers. The existing popup layout/teardown drives backdrop visibility and resizing.

## Module boundaries

[meson.build](../../meson.build) assembles the local Noctalia library and Luciole-owned static modules. [CONTRIBUTING.md](../../CONTRIBUTING.md#module-layering) defines the allowed dependencies. Public domain APIs use `Location`, typed metadata and `CancelToken`; UI callers do not operate directly on GIO file objects.

| Area | Responsibility |
| --- | --- |
| `lib/` | Mirrored renderer, text, scene/input, shared controls, generic Wayland transport and image texture residency |
| `src/model/` | Plain browsing/thumbnail options and shared domain types |
| `src/fs/` | URI-backed locations, filesystem queries, directory sessions, errors and anchored local persistence |
| `src/config/` | Validated settings, GUI overrides, shared bookmarks and private layout/window state |
| `src/browser/` | Published directory model, controllers, selection, history, Miller chains and tab/job routing |
| `src/operations/` | Worker-backed file jobs, conflicts, per-item outcomes and archive services |
| `src/imaging/`, `src/system/`, `src/thumbnails/` | Decoders, artwork resolution, generation providers, metadata and disk cache |
| `src/platform/`, `src/clipboard/` | Luciole-owned desktop launching, decoration, clipboard and native drop transport |
| `src/ui/` | Luciole-specific views and compositions of actual Noctalia controls |
| `src/app/`, `src/event_loop/` | Application ownership, page orchestration, platform polling and GLib integration |

The application uses direct Wayland and OpenGL ES with Pango/Cairo. GdkPixbuf/Glycin supplies image decoding, not a widget layer. Builds consume the checked-in mirror; a sibling checkout and the Noctalia shell are not runtime/build requirements. Generic library changes go upstream before reviewed updates are copied back into Luciole.

## Network discovery

Network is a built-in destination in [PinService](../../src/browser/places.cpp), with its order saved in the private Places layout. Both the normal sidebar and its optional folder tree filter it through `browser.show_network`, independently of the drive-row preference, retaining underlying layout indices for drag/drop. Missing Network slots are appended to existing layouts. Network is not automatically exported to GTK bookmarks, and an explicit existing Network pin is deduplicated. Its row supports local reordering but never file transfer; hiding it leaves direct network addresses and existing views usable. This follows [Thunar's hideable Network shortcut](https://github.com/xfce-mirror/thunar/blob/master/thunar/thunar-shortcuts-model.c), with ordering adapted to Luciole's unified Places list. Creating its row/root only constructs a Location and model entry; it does not enumerate, mount or monitor the destination. No application-wide availability subscription, discovery timer or startup network enumeration is retained.

Opening `network:///` or explicitly expanding its tree root starts [NetworkListing](../../src/fs/network_listing.h) through the cancellable DirectorySession. The composite source uses a shared, on-demand [WsDiscovery](../../src/fs/ws_discovery.h) client and a bounded child session at `dns-sd://local/`. It never enumerates GVfs's aggregate Network or WSDD root, so neither backend nor an external WSD helper is needed. Only SMB-target DNS-SD shortcuts are merged. Real server locations remain `smb://` URIs; discovery labels and stable logical IDs are separate from operation locations. Direct addresses and pinned shares remain independent of discovery. GVfs retains ownership of share browsing, mount/login, file operations and its optional DNS-SD service. Metadata HTTP requests use system libcurl on workers, connecting to the numeric discovery sender with the advertised Host preserved. Proxies and redirects are disabled; HTTP/HTTPS, TLS verification, bounded headers/body, an eight-second deadline and cancellation remain enforced. The worker polls at most 50 ms before rechecking cancellation.

Interface enumeration, monitor construction, UDP sockets, packet/XML parsing, metadata target validation and HTTP/XML metadata requests run on cancellable workers. The main context receives a bounded mailbox and coalesces publications. The last open Network listing releases the shared client without joining a worker. Refresh and network changes cancel the previous generation. The client probes both discovery dialects on multicast-capable IPv4/link-local IPv6 interfaces, correlates bounded Probe/Resolve replies, listens for Hello/Bye, and expires stale records. A ten-second initial window and periodic probes apply only while Network is open. [Wire helpers](../../src/fs/ws_discovery_protocol.h) parse namespaces rather than XML prefixes, reject DTDs and bound document size/depth/nodes. Metadata connects only to the numeric UDP sender, disables proxies/redirects, bounds response bytes/concurrency and cancels at an absolute deadline. A missing name leaves a usable numeric server destination. No background startup scan, server-share enumeration, persisted credentials, Qt/KDE stack, copied third-party discovery implementation or library-mirror change is introduced.

DirectorySession retains a shortcut's validated `standard::target-uri` in its optional shared EntryExtra. The shortcut's own location remains its listing/operation identity; navigation uses the target in activation, new tabs and Miller columns. Missing, invalid and self-referential targets do not launch a default handler. Discovery-directory monitors are created on a cancellable worker, connected on the main context and followed by a refresh to cover the read-to-watch handoff. Navigation and destruction reject late monitor completions. Other remote-folder monitoring retains its existing explicit limitation. Explicit browsing still uses the normal NotMounted mount flow; passive tree enumeration never asks for credentials.

## Mounting browsing locations

[BrowserController](../../src/browser/browser_mount.cpp) handles a distinct NotMounted failure from its passive DirectorySession by starting one asynchronous enclosing-volume mount for that explicit browsing attempt. [LocationMount](../../src/fs/location_mount.h) owns cancellable enclosing-volume and mountable-item GIO requests and [MountInteraction](../../src/fs/mount_interaction.h) bridges password/question signals into typed pending requests. A successful mount, including a concurrent AlreadyMounted result, refreshes the original session without adding another history visit. Other file/network errors are not blanket mount triggers. Explicit refresh permits another attempt; navigation, Stop and controller destruction cancel and invalidate the old completion. Search/tree scanners do not start interactive mounts. Mountable entries, including SMB server shares, use GIO mount_mountable and navigate to its returned folder rather than launching an application or trying to enumerate a mountable object. Only NotSupported falls back to enclosing-volume mounting. The resolved folder replaces the pending history location rather than adding another visit.

[MountController](../../src/app/page/mount_controller.cpp) presents pending requests from the active browsing context through [MountDialog](../../src/ui/dialogs/mount_dialog.h), composed with actual Noctalia controls on the page's explicit-dismiss popup. Request IDs and browser context IDs reject obsolete answers. Background tabs wait for their own presenter; closing a login dialog aborts that request. Default GMountOperation password/question handlers are stopped so their unhandled idle reply cannot race a human response. Provider-supplied messages are bounded, repaired to UTF-8 and displayed literally. Question lists are bounded to sixteen choices. Password-only requests retain the provider's user/domain; guest access requires the provider's explicit anonymous capability. Unknown authentication flags abort with an explicit unsupported-method error.

Credentials stay in the live operation/dialog and go to GIO, with session-only saving when supported. Luciole does not write them into configuration, bookmarks or a password store. The operation and its secret are released/cleared on completion or cancellation. A cancelled or superseded operation keeps only the references required for its eventual async finish. Missing backends remain explicit failures. This is application-owned desktop interaction; no shared Noctalia library, mount helper process or new dependency is introduced. Device unlock/process-blocked prompts and full provider coverage remain unfinished. [Nautilus](https://github.com/GNOME/nautilus/blob/main/src/nautilus-mime-actions.c) likewise requests an enclosing mount, handles authentication and retries access; Luciole supplies its own controls instead of GtkMountOperation.

For an unsupported remote directory-open error, DirectorySession checks GIO's advertised URI schemes on a worker. An absent scheme receives backend/session setup guidance containing only the scheme, without echoing address credentials. An advertised protocol retains its provider's error, and native/Trash errors retain their existing handling. Request identity rejects diagnostic replies after navigation, cancellation or destruction. Only NotMounted starts mounting; an unsupported protocol never triggers an authentication retry.

## Windows, tabs and pages

[WorkspaceApplication](../../src/app/workspace_application.h) owns native windows, the workspace, application-wide preferences and caches, and the [OperationHub](../../src/app/operation_hub.h). The `single_window` preference keeps one browsing window: forwarded launches and FileManager1 requests add tabs to `browsingWindow()` (the focused live browser window, else the first) instead of calling `newWindow()`, New Window degrades to a tab, and Detach is skipped. File chooser windows are unaffected. [TabWorkspace](../../src/browser/tab_workspace.h) represents logical tabs and optional splits. A native host supplies the visible toolbar/sidebar and mounts the active page roots. `TabWorkspace::addTab()` accepts explicit activation intent; background insertion retains the selected tab and its full split layout/focused page, while the first tab of an empty window is necessarily active. Folder-opening workspace commands follow the shared `switch_to_new_tab` preference; explicit New Tab and one-off background commands carry separate intent. Hidden pages initialize their directory controllers normally without mounting their scene or taking focus. Background loading and errors do not select a tab. Middle-clicking a folder in an inactive split pane leaves the original pane focused when opening in the background.

GIO's volume monitor starts its monitor services synchronously, so [DriveMonitor](../../src/fs/drive_monitor.h) starts after a window's first frame; device rows appear through the usual change notification just after. Its constructor still makes the serialized first mount-table query that GIO needs before worker threads query filesystems. The process pins glibc's mmap threshold at 128 KiB, so large listing arrays are mapped separately and return to the system when freed.

[BrowserPage](../../src/app/page/browser_page.h) orchestrates feature controllers rather than implementing file jobs or decoder work. Each page has its own browse controller, selection, history, query and viewport. Its [MillerColumns](../../src/browser/miller_columns.h) chain owns additional lazy controllers within the same page. The focused controller supplies action and preview targets. Offscreen/retired branches release resources; at most 16 live columns remain while deeper navigation retires old ancestors.

Successful Parent Folder navigation returns keyboard focus to the active page's file view immediately; the existing pending-target mechanism selects and reveals the departed folder when the parent listing arrives. The shared focus helper prevents an inactive pane from taking the window's focus. Existing Columns ancestor navigation retains its own focus handoff. [Nautilus's parent-navigation selection calculation](https://github.com/GNOME/nautilus/blob/main/src/nautilus-window-slot.c) also selects the departed folder when navigating to an ancestor. This is a source comparison, without a live Nautilus check.

Page visibility does not confer ownership of running file jobs. Accepted Follow-scope jobs can move to another page when a tab closes; page-scoped preparation is cancelled. The OperationHub also owns bounded recent activity reports and one in-memory native rename Undo/Redo record across pages and windows. Its job ownership/activity adapter is compiled as the internal `luciole-app-jobs` static library so headless tests exercise the actual application lifecycle without UI wiring. See [file jobs](file-jobs.md). Optional last-window tab restoration is persisted in the versioned state store and consumed after a successful restore.

A page's editor registers a [PageEditing](../../src/app/page/page_context.h) through `PageContext::setEditing`: whether it has the keyboard, which keys it takes, whether it holds unsaved changes or is saving, how it asks before the page goes away, and what to do when the page is deactivated with that question open. While the editor has the keyboard, the page offers it every key first, its own shortcuts that stand down for the location field stand down for it too, and the workspace leaves Tab to the page; Ctrl+W, Ctrl+Q, Ctrl+Tab and the other window keys keep working. Closing a tab (the shortcut, its close button, a middle click, the tab menu), closing a pane, leaving split view, closing a window and Ctrl+Q go through one [CloseGate](../../src/app/close_gate.h): it asks each page the action takes away that holds unsaved changes, one after the other, after selecting its tab and making it the active pane, and runs the action once every page has answered, then selects again the tab that was selected before the questions, when it is still there; a page that answers but keeps its changes, because its save failed, ends the request, and a second request while one waits is ignored. A window close, the compositor's included, arrives through `WindowSurface::setCloseGuard`, which keeps the window running while the questions are asked; the window goes once nothing is unsaved or when the gate's action closes it, which asks nothing again. The workspace side of this lives in `src/app/workspace_leaving.cpp`. Detaching a tab or moving it to another window moves the same page with its Workbench session, so it asks nothing. A termination signal asks nothing, and a running save keeps the process alive through `BrowserPage::busy()`. Deactivating a page whose question (`ActivePopup::Kind::SaveChanges`) is open calls `keepQuestion` before the popup closes, so that close is no answer. The gate is compiled as the internal `luciole-app-close` static library so its test runs without a window.

### Adaptive sidebar

[AdaptiveSidebar](../../src/model/adaptive_sidebar.h) separates the saved docked visibility from temporary drawer state. Below 760 logical pixels, the active page presents its Places subtree as a drawer; entering compact mode closes that drawer, and widening restores the saved preference. Compact toggles never write preferences. SidebarController retains the user's width and the reusable Places tree across page switches, while temporary drawers close when the window changes its active page.

[sidebar_drawer.cpp](../../src/app/page/sidebar_drawer.cpp) owns the toolbar toggle, bounded slide animation, scrim, focus and keyboard scope. Animation callbacks belong to the controller and are cancelled on destruction. Panel position and scrim opacity interpolate independently: automatic resizing slides the docked sidebar away without introducing a dimming flash; explicit drawer opening and dismissal fade the scrim. Wide visibility changes also animate the reserved content width. Escape clears the toggle selection and returns focus to the file view. Tab stays within the open drawer. The existing animation manager supplies timing and motion policy; no shared-library edits are needed.

The host arranges the layer below the toolbar and routes covered pointer and external-drop events to the active page before considering panes underneath it. A clipping container keeps hit testing enabled for its children. The sidebar panel sits above a separate outside-click/scroll blocker; file-view click, middle-click, tooltip, column-header and drop probes cannot target obscured contents. Existing Places callbacks, lazy tree sessions, menus, pin reordering and supported folder transfers remain authoritative. Layout owns geometry and visibility; render callbacks do not mutate the scene.

This follows [Nautilus' collapsed OverlaySplitView](https://github.com/GNOME/nautilus/blob/main/src/resources/ui/nautilus-window.blp) and [libadwaita's overlay-sidebar behavior](https://gnome.pages.gitlab.gnome.org/libadwaita/doc/main/class.OverlaySplitView.html), using Noctalia controls and Luciole's existing width preference. Luciole uses a 760-pixel breakpoint and retains the docked preference independently. The comparison is based on primary sources, not a live Nautilus test. There is no new dependency, installed asset, settings key or state schema.

### FileChooser portal windows

`luciole --file-chooser-service` is a separate D-Bus activated process that owns `org.freedesktop.impl.portal.desktop.luciole` and nothing else: no single-instance name and no FileManager1. [FileChooserService](../../src/platform/file_chooser_portal.h) parses each OpenFile, SaveFile or SaveFiles call into a typed request and hands it, with a [FileChooserCall](../../src/platform/file_chooser_portal.h) that owns the pending reply and its exported Request object, to `WorkspaceApplication::choose()`. The call answers exactly once: success, cancellation, or 2 for a frontend Close, a failure or a call dropped unanswered. Close is accepted only from the original caller.

A chooser window is an ordinary host with a single ordinary BrowserPage in chooser mode, plus a [FileChooserSession](../../src/app/file_chooser_session.h) that owns the request, its filters and choices, and the footer. Chooser hosts never save or restore the browsing session, ignore workspace commands and external drops, hide the tab strip and never use Miller columns. Their view mode, sorting, hidden-file visibility, zoom and preview visibility come from and save to the separate `chooser_*` settings, so a picker's layout never changes the browser's. The requested `current_folder` or `current_file` always decides the start folder; without one, `chooser_start_folder = "last"` reopens the folder recorded in `state.toml` when the previous pick was accepted, written by a worker as a last-writer-wins section, and otherwise the picker opens Home. In chooser mode the page never launches files: Open goes to the session, which decides through [chooser_policy](../../src/browser/chooser_policy.h) whether to enter a folder, accept or explain why not. The action registry disables every action outside a fixed list of browsing and selection actions plus New Folder, so menus, shortcuts and controllers cannot start any other file job. A toolbar button shown only in chooser windows offers New Folder, which creates the folder in the current location and selects it. Portal filters hide non-matching files through a `DirectoryModel` entry filter. Links stay visible because listings report them without their target's kind, and the policy resolves the selected ones. A `wayland:` parent handle is imported through xdg-foreign, and the window is made modal through xdg-dialog when the request asks for it.

Saving chooses destinations and writes nothing. SaveFile adds a name field to the footer: it takes keyboard focus with the stem selected, its keys bypass the page's shortcuts, selecting a file or a link to one copies its name into it (a link's target is read on a worker, since it may sit on a slow mount), and a name that is an existing folder enters it. SaveFiles shows folders only and saves the application's names into the current folder. When a destination exists, the first Save only asks, and saving the same destinations again replaces them; navigation or a name edit withdraws the question.

## Asynchronous publication

[DirectorySession](../../src/fs/directory_session.h) enumerates asynchronously and publishes typed snapshots. Ordinary local name-sorted folders above 512 entries use an immutable browse catalogue: raw names share one NUL-separated buffer, display-name exceptions remain separate, and compact rows retain IDs, kinds, hidden/link bits and opaque dirent inode hints. The hints validate directory-entry continuity; they never replace GIO's actual provider identities. Only visible/overscan rows and explicit consumers request detailed facts. A cancellable worker queries GIO in batches of at most 128 rows; at most 1024 detailed rows remain in the current working set. Owner, group, permissions and accessed/created time are requested only for enabled extra columns or explicit consumers. A queried-field mask distinguishes pending optional facts from completed unknown values. Small folders, metadata sorts, selections above 512 entries and expandable trees retain the eager path. Provider, Trash and unsupported local filesystems retain their existing GIO path.

Catalogue snapshots share the immutable names/kinds, and each metadata publication replaces its sparse immutable fact overlay. Retained snapshots and copied operation entries keep their original values. Model name/filter/locale keys and projection indexes survive fact-only publications, avoiding another whole-folder sort. Plain catalogue views do not construct rich entries for every row. A row batch rechecks requested dirent hints and the original parent identity before publishing facts; replacements retire IDs and restart the scan, while unavailable checks disable actions. This validation enumerates directory names without statting every file and handles child mount points without mistaking their dirent hints for actual inode identities.

File actions await required facts and then use the existing capability, context, URI, identity and revision checks. Selection totals show pending sizes explicitly; large selections and metadata sorts prepare complete entries. History resolves only captured references. Duplicate/Miller transitions retain their own captured source payload and cancellable identity query, so closing the original controller cannot lose pending selection restoration. Navigation or destruction cancels that destination's query. Source ownership, rather than a borrowed controller pointer, governs its lifetime.

Outside the catalogue path, Local folders on local filesystems are listed by [native_listing](../../src/fs/native_listing.h) on a worker with `readdir` and one `statx` per entry; every fact equals what GIO's local backend reports, which the session test checks entry by entry. Content types come from `g_content_type_guess`. Names it is uncertain about publish with that guess and `contentTypesPending` set; a second worker pass then reads them through GIO, exactly as GIO sniffs, and publishes the sniffed types and icons after 100 ms, then at doubling intervals up to 1.6 s. A rescan keeps the sniffed type of a file whose size, modification and change times are unchanged. Access read/write/execute are deferred: [entryAccess](../../src/fs/entry_access.h) answers them with `access(2)` for the rows and targets that need them; rename, delete and trash stay in the entry. Network and FUSE filesystems, entries that cannot be inspected and every other provider keep GIO's enumeration. [DirectoryEntries](../../src/fs/directory_entries.h) separates the snapshot header from shared immutable payload blocks. A completed session moves its private entry vector into a published block; controller and model copies retain that generation rather than duplicating the entries. An entry stores its name and a shared folder; `location()` builds the child location on demand, and only entries outside a listed folder hold a whole location. Local entity tags and file identities are numbers whose text forms are rebuilt exactly; display names that differ from the name, provider tags and identities, search context and Trash facts are shared side data. MIME types and owner/group names are interned [InternedText](../../src/fs/interned_text.h) and change revisions are two integers, so a common entry carries no per-entry copies of them. The session's name-to-ID table indexes the published entries instead of copying their names. Operation names and escaped URIs remain separate from display text; sorting or Unicode search must not rewrite operation identities.

Native listings, catalogues included, never follow symlinks. After publication, a worker pass follows each link with `statx` and republishes once it knows which links lead to folders, so Folders First can group them and they show the folder icon in place of the generic link icon; a catalogue records them in an overlay beside its shared names and kinds, and detailed facts keep that kind. Until the pass returns, a link keeps the kind the previous scan of the same folder found, or sorts with the files. Following a link can block without end on an unresponsive network or FUSE mount, and cancellation cannot interrupt it, so the link passes of every session share two workers: hung targets hold at most two GIO pool threads, later passes wait for a free worker (at most 64; beyond that the oldest is dropped), and a pass from a replaced or cancelled scan is discarded when it returns.

An icon pass shares those workers. On a local, non-network filesystem it reads each folder's custom icon with [customFolderIcon](../../src/fs/custom_icons.h): GIO's `metadata::custom-icon`, then `metadata::custom-icon-name`, then `Icon=` in the folder's `.directory`. Links get their icons from the link pass instead: once a link's target has answered, it calls `linkTargetIcon`, which gives a custom icon set on the link or on its target folder, the plain folder icon, or the icon of the target's content type. A link to a hung mount therefore holds only the worker its link pass already holds. The icon pass works in slices of at most 4096 folders and 100 ms, doubling up to 1.6 s. After each slice it publishes what it found and queues again behind the other passes, so a folder with thousands of subfolders does not keep a worker from them. The session keeps the results by name as overrides of the listing's icons. It applies them, only to folders and links, to the published entries, and in a catalogue to each row's facts as they arrive. A rescan keeps the previous overrides until the pass that reads them finishes, then drops those it did not find again. A dangling link keeps the link icon.

Change notifications rescan after 80 ms, or after twice the previous scan's duration when that is longer (at most 2 s). A scan that finishes after further changes is discarded and rescheduled, unless nothing was published for a second: then the session publishes it, keeping the IDs monitor events maintained meanwhile, and rescans. A folder that changes continuously therefore still updates about once a second. Publishing or replacing a listing of 10,000 entries or more schedules a low-priority `malloc_trim`.

[DirectoryTree](../../src/browser/directory_tree.h) shares its root and child payloads. Expanded rows use an index projection that retains the underlying blocks, including after a source session is collapsed or replaced. A tree-owned identity registry supplies child IDs when entries are constructed; URI/identity checks preserve surviving IDs and independent occurrences keep separate IDs. Unexpanded trees share the root directly. [RecursiveSearch](../../src/fs/recursive_search.h) publishes immutable matching batches and concatenates block references. New collections retain payload blocks directly, without retaining chains of older projection tables. Search notification cadence and model sorting still have their existing costs.

Published entries expose no mutable access. Refresh invalidation that changes access facts creates a replacement payload once for that invalidated generation; retained snapshots keep their original facts. A completed scan replaces that payload, and late callbacks remain guarded by session generation/cancellation. Views borrow entries only until the next model mutation; consumers needing a longer lifetime must retain the collection or copy the required operation facts. Sharing does not change metadata completeness, raw names, selection or job revalidation.

The model caches name/filter keys by stable ID when the display name and containing location remain unchanged. Presentations live in a vector indexed like the snapshot's entries and hold offsets into one key buffer; an open-addressing ID index and a per-entry row index replace per-ID hash nodes, and a filter key is stored only when folding changes the display name. Type, Owner, Group and Location collation keys are prepared only when selected, before sorting, and shared for repeated values or parent URIs. One alternate-field pool is retained per snapshot; refreshed metadata invalidates it. Pointers into that private pool survive rehash and never escape the model. Raw operation names, locations and provider metadata remain authoritative.

Selections, focus and anchors use stable entry IDs, not row indices. Refresh preserves surviving identities; deletion/replacement retires them. Controllers reject old generations. A pointer release must not activate a different entry after a virtual row is rebound.

When a completed same-location snapshot removes the cursor's ID, DirectoryModel searches the previous visible order forward and then backward for a surviving visible ID. Remaining selected items receive cursor priority; when the selected cursor was the final selected item removed, its successor becomes selected and the range anchor follows. A cursor without selection stays unselected. Newly inserted or replacement IDs cannot become fallback targets, and an empty expanded branch cannot move selection into another branch. The old order is retained only for an actual removed cursor, keeping ordinary metadata publications on their existing path. Filtering, navigation, cancellation, partial/error listings and fresh incremental loading do not trigger this continuation. [Nautilus's display_pending_files](https://github.com/GNOME/nautilus/blob/main/src/nautilus-files-view.c) similarly preserves a nearby cursor when processing removals loses view focus; Luciole uses surviving identities rather than a row-number fallback. This is a primary-source comparison, without a live Nautilus check.

The main loop integrates the default GLib context through [GlibPollSource](../../src/event_loop/glib_poll_source.h), alongside the shared Wayland and deferred-call sources. Workers perform filesystem traversal, decoding, provider work and configuration reads/writes. Completion callbacks verify cancellation, captured context and owner lifetime, then request Update/Layout/Redraw. Rendering must not perform I/O or rebuild the scene.

Relevant regressions include [directory sessions](../../tests/directory_session_test.cpp), [models](../../tests/directory_model_test.cpp), [Miller columns](../../tests/miller_columns_test.cpp), [tab workspace](../../tests/tab_workspace_test.cpp), [job routing](../../tests/job_routing_test.cpp) and [input lifetime](../../tests/input_lifetime_test.cpp). GUI ownership and compositor behavior also need isolated real-window checks; headless contracts alone do not establish them.

## Folder measures

Workbench sizes its pieces by what lies below each folder. [measureSubtree](../../src/fs/subtree_measure_walk.h) walks one local folder on the calling thread with directory descriptors: `openat` with `O_NOFOLLOW` for each folder, a listing read through a duplicate of that descriptor, and one `statx` per entry with `AT_SYMLINK_NOFOLLOW` and `AT_NO_AUTOMOUNT`. It follows a symlinked root but no symlink below it, never enters a folder on another device or behind an automount point (such folders are recorded and flagged), counts each folder once by inode, and keeps an explicit stack instead of recursing. A hard-linked file adds its bytes and counts as a file at its first name only; up to 100,000 such inodes are remembered, and past that bound later names count again and the table says so. Remote and FUSE filesystems are refused.

The result is a flat table with one record per folder down to the detail depth, three levels below the root by default. Parents precede children and each folder's child records are contiguous. A record holds the totals of everything below the folder (apparent bytes, allocated bytes, files, direct items, newest modification), its flags (partial, unreadable, other filesystem, truncated, hidden, and folders omitted for a record at the detail depth that holds folders without records), its stamp (device, inode, and modification and change times in seconds and nanoseconds) and its 24 largest files, with the other files folded into one remainder. A folder with more than 512 child records keeps the largest when it finishes and folds the others, with everything below them, into a second remainder. Deeper folders only add to totals. An entry budget of two million, a deadline, a depth limit of 128 and a `CancelToken` stop a walk: a limit marks the open folders truncated, so their totals are lower bounds, and a cancellation leaves them partial. While it runs, the walker hands out a copy of the table at an interval the caller chooses, in which every open folder already carries what was counted below it and the folder being read shows the files it kept so far, so totals never decrease from one copy to the next and each folder's bytes are the sum of its pieces. A listed folder's file list is immutable and shared by every copy, so a copy duplicates only the small per-folder records.

[SubtreeMeasureService](../../src/fs/subtree_measure.h) runs walks on two threads of its own, so a long walk never occupies the shared GIO worker pool that listings, fact batches and thumbnails use. Requests carry a priority (Current, Ahead, Jump, Ancestor) and run in that order, then in request order. A request for a location that is already queued or running shares that walk and may raise its priority; dropping the last handle withdraws a queued walk or cancels a running one. Ancestor walks run under a smaller entry budget and a two-second deadline. Workers store their latest table under a lock, and a 100 ms timer on the default main context publishes each one as an immutable shared snapshot and notifies, the way FolderTotalsService publishes progress. The timer stops when no walk remains.

[MeasureCache](../../src/browser/measure_cache.h) is one instance shared by every tab and window, keyed by location. It serves the last complete table, flagged stale, while a new walk runs. When a table is older than five seconds, the folder's current stamp is read on the worker pool and compared with the stamp of the table's root; a difference starts a walk. A table older than a minute is walked again regardless, because a change deep below a folder leaves its stamp alone. A table that an Ancestor walk left truncated is walked again as soon as a more urgent request asks for it, since only Ancestor walks run under the smaller budget; each handle reports the priority its table was walked with. `invalidate()` marks a location and every cached ancestor stale for change notifications; a walk running at that moment delivers a table that is already stale. A folder inside a cached table is found without a walk of its own. `view()` hands out the tables and their flags as they are at that moment, in an immutable `MeasureView` a worker may read while the cache moves on; the cache keeps one view until a table, a stale flag or a walk changes. A page takes a lease on each folder it wants walked; when the last lease of a folder goes, the cache cancels its unfinished walk and forgets a folder that has no complete table, so a walk nobody waits for stops at once. Once the cache holds more than 250,000 records, the least recently used tables go first, never the most recent one; a table without records, such as the error table of a missing folder, counts as one. The cache itself never touches the disk.

[buildMeasuredTree](../../src/browser/measured_tree.h) turns cached tables into the immutable `workbench::Tree` the layouts read: the current folder with three levels below it, and one node per ancestor holding its entries, with the folder on the path in its own place. That place is the child record or file (a symlink) of its name; when the parent has neither, the folder was folded, and it is taken out of the parent's folder remainder. Levels the cache does not know come from the caller's listings, flagged partial, with folder sizes unknown and direct item counts when the caller has them. A record whose folders were omitted is flagged truncated below the current folder, and gives way to the caller's listing as the current folder or an ancestor. Remainders become nodes with an empty name, listed beside the tree; their items count the folded entries. Visit counts come from a lookup the caller passes in. Building reads only memory, and a node limit flags folders whose entries would pass it as truncated.

Regressions: [walker](../../tests/subtree_measure_walk_test.cpp), [service](../../tests/subtree_measure_test.cpp), [cache](../../tests/measure_cache_test.cpp) and [measured tree](../../tests/measured_tree_test.cpp).

## Workbench model

[WorkbenchServices](../../src/browser/workbench_services.h) holds the measure service, with two walks at once, and the cache over it, with a budget of 250,000 records: one instance for the application, handed to every Workbench page.

[WorkbenchWalks](../../src/browser/workbench_services.h) are the walks one page asks of that cache, started in a fixed order: the current folder first, whose walk lists the children at once and records the two levels below them as it goes, and any child invalidated since; then the folders of the Jump Ahead rows, once the folder's own walk has finished and a snapshot of it has been ranked; then each ancestor, nearest first, under the service's ancestor budget. At most two of a page's walks are queued or running at once. Each started walk holds a lease in the cache. Leaving a folder drops its walks, and the cache cancels each one no other page holds, so the next folder's walk does not wait behind them; a running walk the new folder also wants, such as that of the folder left when it becomes an ancestor, goes on for the new folder. Two pages on the same folder share one walk, because the cache does, and it ends only when both have left. A started walk is read back with `find()` once its folder has a table of its own, so a walk that ends stale, because something below its folder changed meanwhile, is not started again; only a folder invalidated itself while its walk ran is walked once more. A walk asked again starts no sooner than one second after its last walk ended, nor sooner than four times as long as that walk took, so a folder that keeps changing is walked a few times rather than back to back. A walk without the ancestor budget that ends with a table that budget cut short is walked again in full.

[WorkbenchModel](../../src/browser/workbench_model.h) is the measured picture of one page. The page tells it its folder, the layout settings (hidden entries, size by, color by, emphasis) and a source of visit counts, which it reads for everything below the outermost folder shown whenever the folder changes and whenever the page passes the source again, as it does each time the visit service reports a change. The service reports recorded visits within about a frame, once for a burst of them, long before it writes them. While the ancestors wait for their walks, a worker lists each of them, up to 4,096 entries, so their levels show their entries by name and kind, with folder sizes unknown, from the first snapshot on.

A cache notification that changes one of the tables the picture is built from schedules a build, at most once every 100 ms. The main context hands a worker the cache's view and pointers to the page's inputs. The worker builds the tree with `buildMeasuredTree` from that view, and a refreshed child's levels only when its table changed, then grafts the refreshed children into one copy of the tree, sets visit counts, ranks Jump Ahead, computes the shares of the folder's entries and compares the result with the published snapshot. New settings or visits run only that worker step again, on the last tree. A build for a folder left behind is dropped, and one still queued never runs. A result equal to the published snapshot, apart from the build time, publishes nothing; otherwise the main context swaps in the new immutable [WorkbenchSnapshot](../../src/browser/workbench_snapshot.h) with the next serial and notifies. A snapshot holds the tree, the Jump Ahead rows with the folder of each row, the shares by entry name for the weight bars of list rows with the total weight of the visible entries, and the error when the folder could not be measured. An entry the tree does not name, such as a file beyond the 24 largest or a folder beyond the 512 largest that the walk folded into a remainder, weighs its listing's own values over that total. Nothing is published for a folder until its own walk, or a cached ancestor's table, lists its entries, so the first snapshot already shows every child, flagged partial while it is measured. `measuring()` stays true while the folder's walk or a refreshed child's has not finished, the ancestors are being listed, or newer tables or settings have not been published yet; Jump Ahead and ancestor walks only refine the picture.

`invalidateChild(name)` walks that child of the folder alone and grafts its new levels over the folder's table, adjusting the folder's totals; its siblings are not walked again, even when the folder's own walk was running at that moment. A child that is gone leaves the picture. The whole folder is walked again instead for a file child, since only the folder's walk measures files; for a child that the folder's finished table does not record while it folds folders into a remainder, since that remainder may count it; and once 16 children were walked alone, so each build stays bounded. A local folder is watched with a [FolderChanges](../../src/browser/workbench_services.h), which hands what changed in it to `invalidateChild` at most once every 100 ms; a change of the folder itself, or of more than 16 entries in that time, walks the whole folder again instead. Destroying the model never blocks: walks no other page holds are cancelled, a running build or listing is dropped, and the owner may destroy it from its changed callback.

Regressions: [services](../../tests/workbench_services_test.cpp) and [model](../../tests/workbench_model_test.cpp).

## Columns ahead

[LookaheadColumns](../../src/browser/lookahead_columns.h) owns the listings of up to three read-only columns ahead of a Workbench list: one `BrowserController` per shown column, in the user's sort order and hidden setting, loaded on worker jobs like any other listing. Nothing in it selects, navigates or reads any other controller.

A `LookaheadRequest` says what to follow. Column one lists the target when it is a folder: the page state's target, or with none the `a` of `workbench::columnChain`, the remembered or heaviest folder. Each later column lists the entry of the column before it that its pin names, otherwise the chain rule's pick (the `b` and `c` of `workbench::columnChain` for the page's measured tree), and either one counts only when it lies directly in the folder that column lists. A file ends the chain and becomes the preview of the next slot; a file target gives a preview and no listing. Repeating a request changes nothing.

A listing that leaves the columns is stopped, which ends its enumeration and its folder monitor, and is kept with its rows, at most three of them, so a target that comes back refreshes in place instead of starting empty. A folder moving from one column to another keeps its running listing. Older listings are retired and freed by `collectRetired()` once the view has dropped their models. At most three listings run at any time, however many folders the target sweeps across. A shown folder that disappears or cannot be read keeps its column, whose model reports the error. Changes bump a serial and call one callback.

[WorkbenchState](../../src/browser/workbench_state.h) is the small state the parts of a Workbench page share, with no view code. It holds the hovered entry with the pane that set it (a pane clears only its own hover), the list's cursor entry, the pointer target, the pins of columns one and two, and whether the instrument covers the page. The target is the pointer target while there is one, else the cursor entry. Time is passed in: a pointer that rests within 6 px for 250 ms on a list row makes it the target, and on a row of column one or two makes it that column's pin; a pin in column two also pins the folder that column lists, so a pick that changes cannot take the column away. Travel beyond 6 px or another row starts the wait again. Leaving the list and the columns for 300 ms, or pointing at empty list space for as long, falls back to the cursor. A click pin holds off pointer changes until it is released, the cursor moves or the folder changes. While a preview is edited the state is frozen: the pointer starts no wait and no release, so nothing is due, and a cursor that goes away with no new one is held until another cursor or a folder change, also after editing ends; a save renames a new file over the old one, the listing gives it a new identity and drops the list's cursor with the old one. `deadline()` says when `advance()` next has work. Every visible change bumps a serial.

Regressions: [columns ahead](../../tests/lookahead_columns_test.cpp) and [page state](../../tests/workbench_state_test.cpp).

## Workbench page

`WorkspaceApplication` owns one `WorkbenchServices` beside its `VisitService` and hands it to every page's `WorkbenchController` (`BrowserPage::workbench()`), next to the visit recorder. Pages are destroyed before it, because every page model borrows its cache. The application also owns the one `TextTileService` the column previews draw text with, whose worker thread sleeps while nothing is queued, and lends it and its `ThumbnailService` to the pages through `WorkbenchServices::setPreviewWorkers`: `browser` cannot include those modules, so it only carries the two pointers. Pages are destroyed before both.

[WorkbenchController](../../src/app/page/workbench_controller.h) is the page's Workbench feature. Its frame slot in `prepareFrame` compares the page's mode with what is mounted. Entering the mode creates a [WorkbenchSession](../../src/app/page/workbench_session.h), and leaving it destroys the session. The session owns the page's `WorkbenchModel`, `LookaheadColumns` and `WorkbenchState` and creates the `WorkbenchView`. It moves the page's file pane, with the details header, notice, list, scrollbar and drop target, into the view's list region, and puts the view at the pane's index in its parent. Its destructor clears the view's sources, takes the pane back, puts it at the view's index and frees the view; the shared cache cancels the walks no other page holds. The session sits in the internal `luciole-app-workbench` library, so a headless test drives it with a real browser controller and a real cache. `~BrowserPage` closes the session before the scene goes.

The file pane is moved, not copied, so `fileList()` stays the regular list and `browser()` stays the page's own controller. Every action, the status bar, the details header, typeahead, rename, drags and drops act on it exactly as in List view, which `showsDetailsRows` treats alike. The columns ahead are separate listings that never become the page's browser.

Each frame the controller reads a `WorkbenchFeed` from the page's browser: its folder, the entry under its cursor, and its sort and hidden settings. The session pushes only what changed: the folder to the model and the view, the listing options to the columns ahead, the layout settings to the model, the choices and the cursor to the view. It then calls the view's `update()` before the page lays out. The controller records every folder the page enters in a `FolderTrail`, which the view hands to the columns ahead and to [WorkbenchParts](../../src/ui/workbench/workbench_parts.h). That one maps it to the nodes of each new snapshot and gives it to the instrument and the ribbon with their other inputs; the Iris hub draws its chips from it, so they stay the same across a switch of instrument. The model, the columns ahead and the view request frames through their callbacks. A timer set to the page state's `deadline()` brings the frame that ends a pointer rest without motion. The page's pointer hook reports list rows under the pointer to the state; the quiet columns report their own. When the pointer moves to the other pane of a split or to the tab strip, `WorkspaceApplication` calls `BrowserPage::workbench().pointerLeft()` on the page that had it, which ends the list's hover and rest there.

The expanded instrument hides the view's center slot, but the file pane inside it keeps its visible flag and its last geometry. `WorkbenchSession::showsPane()` checks every node from the pane up to the view, and the controller's `coversFilePane()` is true while it fails. The pointer hook, the page's middle-click, notice menu, header menu, horizontal wheel and tooltips, and the drop targets through `PageContext::filePaneCovered()` all check it before testing a point against the pane or the list.

The view's requests come back through the controller. Folders open with `browser().open()`, so history, Back and Forward work as everywhere else; a middle click opens a new tab as the list does. A file is launched through the page's launcher, which records the visit. A selection inside the folder moves the list's cursor; a deeper one opens its folder and selects it on reload. A context request on an entry of the folder selects it and opens the page's file menu; other entries get a menu with Open, and Open in New Tab for folders. Header switches write `workbench_instrument` and `workbench_ribbon`. A committed geometry is converted to settings by [workbench_preferences](../../src/ui/workbench/workbench_preferences.h) and only the fields that changed are submitted, once per release, never per motion. The entry another pane points at is marked in the list through `FileViewAdapter::setLinkedEntry`, which rebinds the two rows that change. Changed settings reach the view through `applySettings`: geometry only when it differs, with the expanded flag kept, since settings do not hold it.

The page reports no docked preview in this mode, so the host gives the page that width. The session puts a [ColumnPreviewView](../../src/ui/workbench/column_preview_view.h) in the slot of the file the columns stop at: a header with the file's name, an Open button and its type label, a line of facts, then one content node or a sentence. Its text takes `quietTextSize` for the slot's column, below the list's. The controller owns a [WorkbenchPreview](../../src/app/page/workbench_preview.h) over that view while the mode is on. After layout, in `BrowserPage::prepare`, its `place()` asks the session's `ColumnPreview` for the entry: it looks the entry up again whenever the columns ahead or the list's generation changed, so a file that changes on disk or whose details arrive later shows its new facts and loads again.

[columnPreviewKind](../../src/ui/workbench/column_preview_content.h) picks the view from the content type and the name, first match wins: anything but a local regular file keeps the page's preview; CSV, TSV, XLSX and ODS (`tableSource`) are a table; an STL, OBJ, PLY, glTF or GLB name (`meshFormat`) a model; an archive the archive reader opens (`isSupportedArchive`) a listing; GIF, PNG, APNG and WebP an animation; video and audio, by type or by name when the type is unknown, playback when `MediaPlayer::available()`, else the still; other images the still; text by type or by `formats::fileKind` colored text; an unknown or empty type the bytes; everything else the still. Where the type is not enough the loaders look at the bytes. [column_preview_loads](../../src/ui/workbench/column_preview_loads.h) has one load per kind, each putting its view into the slot at once:

- Text and unknown bytes: `startTextDocumentLoad` into a `TextTileView`, which shows the text, a hex dump when the bytes are not text, or the notice for private key material, whatever the type said. The line count is a fact only for a text read whole, not for a Cut one.
- Tables: `startTableLoad` into a `TableView`; a sheet picked in its sheet list loads again with that index and cancels the read before. Rows and columns are a fact only for a grid without `rowsCut`. CSV and TSV grids come from `delimitedDialect` and `delimitedGrid` in [table_loader](../../src/thumbnails/table_loader.h), which an editor also calls on bytes it holds.
- Archives: an `ArchiveService` of the load's own reads the catalog with a 15 s limit and the service's entry limit; the load lets it go in its frame update, never inside its callback, and builds the `archiveGrid` table and the `archiveMemberCount` fact on a worker. Both take only the archive's own entries: a folder the reader adds for a member's path keeps `ArchiveEntry`'s default mode, which a stored folder replaces with its own. An archive that asks for a password lists nothing. One past a limit, or needing a tool or part it lacks, shows the reader's sentence; a damaged, unreadable, changed or forbidden archive shows a sentence of the preview's own.
- Models: `loadMeshPreview` on a worker into a `MeshView`.
- Animations: an `AnimatedImageView`, whose `sourceSize()` gives the facts their pixel size once it moves. While its state is not Animated the page's preview lies over the slot; Still or Failed sends the file back to that preview for good and frees the view.
- Video and audio: a `MediaView` on the file's path, with the `ThumbnailService` preview image as its poster once it is ready. Nothing decodes before Play. The request carries the sound visualizer's choice, which `WorkbenchPreview::setAudioVisual` also passes to the load in place, and the media view's visualizer buttons report the user's choice back through the preview's hooks for the page to save.

Kinds that keep the page's preview, and an animation until it moves, go through the overlay hook: the controller gives `PreviewController` a `PreviewTarget` with the entry, the slot's scene rectangle below its header less half the column divider's hit area (`previewBounds`) and the header's text size, and replaces it whenever the slot moves or that size changes. The preview controller then shows the same service's snapshot there in a `ColumnPreviewPage` (`ui/workbench/column_preview_page.h`) instead of its pane: the picture, the service's sentence and text, and the snapshot's preview facts under "Details", all at the header's size, which stays below the list's. The slot's header already names the file and holds Open, so the view repeats neither and has no buttons. The quick preview takes precedence and shows the selection while it is open.

A file the cursor moves to waits `WorkbenchPreview::kDwell` (the page state's rest, 250 ms) before its load starts, so keys held down across a folder load nothing; a target the pointer rested on, or a pin, which waited or meant it already, loads at once. A dwell timer brings the frame. A newer file drops the load in flight: each load cancels its token or service in its destructor and its callbacks check a lifetime first, so a late result never reaches the view. One load is held at a time and frees its view with it, when the file changes, when the columns stop at a folder (at once, from `onPreview`), when the slot is hidden, which keeps the file and loads it again once the slot shows, when the page is hidden (`BrowserPage::hide` calls `WorkbenchController::hide`, since a hidden page gets no `prepare` that would see the slot go), which keeps the file the same way, and when the mode ends, since the controller drops the preview before the session.

The controller's key hook runs before the page's shortcuts. Escape minimizes an expanded instrument, except while a text field of the location bar has focus: that Escape reaches the location bar, which cancels the edit or closes its completions. While a part of the view outside the file pane has focus, its navigation keys go straight to the dispatcher. `escapeGesture` cancels a divider drag in the view. A pointer press on a divider takes the focus while it lasts, and `PaneDividerFocus` ([pane_divider_focus.h](../../src/ui/controls/pane_divider_focus.h), fed by each window's dispatcher) gives it back to the area that had it when the press ends, if that area is still in the scene and focusable; a divider reached with Tab keeps the focus and its arrow keys.

## Saving edited files

An edited file is saved only through [user_file_save](../../src/fs/user_file_save.h). Luciole's own settings, state and bookmarks keep [atomic_file](../../src/fs/atomic_file.h), which locks, forces mode 0600 and refuses links; none of that is right for a user's document.

`readUserFile` follows symlinks, reads at most a caller-given number of bytes of a regular file and takes a `UserFileIdentity` (device, inode, size, and modification and change times in nanoseconds) from the same descriptor, before and after reading; a file that changes while it is read is an error. `saveUserFile` takes the location, the new bytes and that identity, and returns a typed `UserFileSaveResult`:

1. The location must be local. Its symlinks are resolved, so the save replaces the target in the target's folder and the link stays a link.
2. Folders, devices, pipes and sockets are refused, and so is a file with more than one hard link, because a replacement would separate its names.
3. The file is opened without following links and its device, inode, size and modification time must equal those from the read; anything else is `ChangedOnDisk` and nothing is written.
4. A folder the process may not write into is `ReadOnlyFolder`; a file it may not write, or one marked append-only or immutable, is `ReadOnlyFile`. This is told before a moved change time, which a change of permissions alone causes, so a file made read-only since the read is reported as read-only. For a writable file a moved change time is `ChangedOnDisk`, like any other change of its identity.
5. The bytes go to a new file in the same folder, created exclusively under a random name. It takes the original's owner and group, then its extended attributes and POSIX access control lists (attributes the folder adds by default are removed), then its mode. When the owner, group or mode cannot be kept by this user the save is refused with `OwnerNotKept`, and an attribute that cannot be copied gives `AttributesNotKept`, since silently changing them would damage the file.
6. The new file is flushed to disk, the original's identity is checked once more, and the new file is renamed over it. The folder is then flushed; if that fails the result is `SavedNotFlushed`. One process-wide lock holds the last check and the rename together, so of two saves of one revision in Luciole only the first succeeds and the second is `ChangedOnDisk`. Another process can still change the file between the check and the rename.

The returned identity is taken from the new file after the rename, so a following save needs no read. On every refusal and failure, including a cancellation, the temporary file is removed and the folder lists exactly what it did before; no lock file is ever created. A reader of the real name sees either the old file or the complete new one.

`startUserFileRead` and `startUserFileSave` run the two on a worker through `runJob` and deliver on the caller's main context. A save always delivers its result, also after a late cancellation, because the file may already have been replaced; the caller checks its own lifetime.

`userFileSaveRefusal` answers, without writing, the refusals a save would give before it writes: not local, gone, not a regular file, hard-linked, read-only, or in a read-only folder. It resolves the file and checks the folder and the file as `saveUserFile` does, with no expected revision.

The editor keeps the file's text form with [text_facts](../../src/formats/text_facts.h): whether the bytes are valid UTF-8, a leading byte order mark, the line-ending style (LF, CRLF or CR, the most common when mixed) and whether the file ends with a newline. `editorText` removes the mark and turns every ending into LF; `fileBytes` restores the mark and writes the recorded ending. Text that was not edited converts back to exactly the original bytes unless the endings were mixed.

`src/editing` holds the editor's models, which use only `formats` and the standard library and do no I/O; the caller passes the time that groups typing. [TextBuffer](../../src/editing/text_buffer.h) keeps valid UTF-8 lines joined by LF with a selection. It refuses text over 1 MiB, a line over 16 KiB, invalid UTF-8 and CR or NUL bytes, and refuses, whole, an edit that would break one of those limits; inserted CRLF and CR become LF. Its undo history keeps at most 1000 steps and 8 MiB of changed text, joins typing within one second, and remembers the latest 4096 revisions for marking a save. [text_motion](../../src/editing/text_motion.h) moves by clusters, words, lines and the document. [SourceStyles](../../src/editing/source_lines.h) colors lines on demand with the preview's tokenizers and roles, keeps 256 styled lines, rescans after an edit only until a line starts in the state it had before, and shows Markdown as source. [TableSession](../../src/editing/table_session.h) edits a delimited file of at most 1 MiB, cell by cell and by whole rows and columns, through the `formats` writers and keeps at most 100 undo steps and 16 MiB of snapshots. [EditGate](../../src/editing/edit_gate.h) holds the rules of enabling editing, saving, and the question asked before unsaved changes are left.

A [TableView](../../src/ui/controls/table_view.h) in editing mode only asks; its owner holds the file, applies each change and sets the new grid with `replaceTable`, which keeps the selection and the scroll position on the same source cell, or the nearest one left. Enter, F2, a double click or a typed character open a one-line field over the selected cell with the owner's whole text (`cellText`, since the grid cuts cells at 256 bytes and shows control characters as spaces; without it no field opens); Enter, Tab and Shift+Tab commit and move, Escape cancels, and losing focus or scrolling the cell out of view commits. An owner calls `commitField` before it asks whether the file has unsaved changes, since a close that leaves the focus alone commits nothing. A commit that changes the text reports `onCellEdited`, Delete and Backspace report an empty cell, and the edit bar, Ctrl+Z, Ctrl+Shift+Z and Ctrl+Y report `onEditRequest` with the selected cell's source row and column while the owner says the edit is available; after a press on the bar the grid has the keyboard again. Ctrl+S commits an open field and reports `onSaveRequested`. An owner offers keys to `offerKey` before its own shortcuts: while the field is open (`editingCell`) every key but Ctrl+S goes to it, Tab included, and while a message hides the grid the table takes none. Regressions: [table view editing](../../tests/table_view_editing_test.cpp), [its keyboard focus](../../tests/table_view_editing_focus_test.cpp) and its [pixels](../../tests/table_view_editing_pixels_test.cpp).

A [CodeEditorView](../../src/ui/controls/code_editor_view.h) edits a caller's `TextBuffer` in place, colored by the caller's `SourceStyles`, and every change to the buffer goes through it. Each line is one texture drawn by a [TextLineStrip](../../src/imaging/text_line_strip.h) in the preview's fonts and palette colors, so the editor's text matches the read-only preview pixel for pixel; [LineStrips](../../src/ui/controls/code_editor_lines.h) keeps the textures of the lines in view and four beside them, redraws a line only when its content or style changes, and moves the others when lines are inserted or removed. After an edit the view tells the styles which lines changed and redraws those the styles report. `update()`, called once per frame before layout, draws missing strips for about 4 ms, the caret's line first, and asks for another frame for the rest; a line wider than one texture keeps the window around the viewport and is drawn again when a sideways scroll leaves it. The sideways extent is the widest line measured so far. The caret blinks as the toolkit's field does, Up, Down and the page keys keep its position in pixels, and the selection is drawn behind the text in `PrimaryContainer`. Copy and cut set the caller's `TextClipboard`; paste inserts the answer unless the text changed or the view lost the keyboard meanwhile. As a `TextInputClient` it commits an input method's text into the buffer and draws text being composed underlined at the caret, outside the buffer. `key()` returns false for keys it leaves to the page, so an owner offers it keys first, Tab included, since the input dispatcher moves focus on Tab before an area sees it. A refused edit reports the buffer's sentence through `onRefused`. Hidden, it holds no texture and stops the blink; destroyed, it leaves no timer and ignores a late clipboard answer. Regressions: [keys](../../tests/code_editor_keys_test.cpp), [pointer, clipboard and input methods](../../tests/code_editor_pointer_test.cpp), [strips and costs](../../tests/code_editor_view_test.cpp), [helpers](../../tests/code_editor_lines_test.cpp) and [pixels](../../tests/code_editor_pixels_test.cpp).

A Workbench column preview edits text through [PreviewEditController](../../src/app/page/preview_edit_controller.h), which drives an `EditGate` and holds no rule of its own. `WorkbenchController` makes one per page on first use and keeps it for the page's life, so it outlives the mode's view; `BrowserPage` registers it as the page's `PageEditing` through [pageEditing](../../src/app/page/preview_edit_page.h), which also shows its question as the page's dialog. `WorkbenchPreview::setEditor` attaches it to the slot's `ColumnPreviewView`, and the preview's destructor detaches it. Saves run `startUserFileSave` with the identity read or last saved, from the model, so they work after the view is gone; every refusal becomes one sentence (`saveSentence`) in the bar, or in the question while it is open.

Before `place()` follows a target, it asks the controller's `follow()` with the file the columns aim at, its listing entry and whether the slot shows: while that is the edited file, the editor keeps the slot, the facts line takes the entry's listed size and date, and [EditedListing](../../src/app/page/preview_edit_listing.h) compares them with the revision read or saved: a change shows the changed-on-disk notice; a file the listing does not hold, as under a filter, shows none, and a save of a file that is gone is refused anyway. The preview sets the page state's frozen flag from `gate().editing()` and its cursor hold from `holdsCursor()`. ## Self-drawn shapes

[ShapeView](../../src/ui/controls/shape_view.h) is the control that draws a scene of shapes and labels: one batch node for every shape, a pool of at most 160 text nodes for labels, and one input area over the whole view.

[ShapeBatchNode](../../src/ui/controls/shape_batch_node.h) is a `CustomDrawNode`. Setting its shapes builds vertex data with `workbench::buildShapeMesh`, whose header documents the vertex layout and the distance functions; the first draw after a change uploads it into a vertex buffer, and every draw is one `glDrawArrays` under the node's transform, opacity and clip. [ShapeBatchProgram](../../src/ui/controls/shape_batch_program.h) is the `RenderExtension` that holds the GLSL ES 1.00 program. Rectangles, rounded rectangles, circles, lines and ring sectors are quads whose fragments evaluate a signed distance, so their edges are antialiased over one device pixel at any scale, fractional ones included; ribbons are strips with a fringe whose coverage comes from the vertices. Fills, strokes inside the edge, hatch stripes, dashed strokes and per-shape opacity are mixed in the shader, and the output is premultiplied.

The program shares the context with the toolkit's own drawing, which uses client-side vertex arrays and caches blending and scissor state. A draw relies on the blending, viewport and scissor that `RenderContext` sets for every node, changes only the program, the array buffer binding and the attribute arrays at its own locations, and restores all three before it returns. Only the program creates, fills and deletes vertex buffers, while its context is current: a node holds a handle, and a handle no node holds any more is deleted on the program's next draw. When the context is lost the program forgets its buffers and every node uploads again.

`ShapeView::setScene` takes a `workbench::SceneShapes`. Without a transition time, without an animation manager, or with motion disabled through `MotionService`, the scene is shown at once. Otherwise one `AnimationManager` tween drives a `workbench::ShapeTween` from what is drawn now, mid-transition included, to the new shapes: each frame replaces the drawn shapes and rebuilds the mesh. No node changes size while it runs, so the window is not laid out again. Labels start from where they are drawn too: a label whose node and text stay moves to its new place; other labels fade out or in. Texts, sizes and widths are set when a transition starts, and labels that left are hidden once it ends. Layout reads the render scale and rebuilds the mesh when it changes, and reports a size change to the owner, which builds its scene for the new size.

A Workbench part fits its scene's labels before the view gets them, in one place: [fitShapeLabels](../../src/ui/controls/shape_labels.h), measured with the part's regular and semibold label metrics. A name (`LabelFit::Shorten`) shows whole, or cut in the middle with at least three characters on each side of the ellipsis and an extension of up to eight characters kept whole, or not at all. A count or a measure (`LabelFit::Whole`) shows whole, else its short form ("+12" for "+12 more", the size alone for a size and an item count), and is never cut; every part's builders mark their counts, sizes and values this way. The Atlas fits its circle and chip names by the same rule before it sizes their pills. A label's trail, the measure at the right end of a one-line Nest tile or the line under a name or a count, becomes a whole label of its own only while that label shows, and the line under a count only while the count shows whole; a measure at the end of the line goes before the name gives way. The text nodes lay the fitted text out whole and never cut it again, so a label whose summed advances fit its box draws whole even where shaping runs a pixel wider. Labels are drawn regular or semibold (`LabelWeight`): names in the Nest, on Atlas pills and chips, and the Iris hub's name and total are semibold, and the hub lays them out at their semibold widths. The Nest lays its core out with [layoutNestTiles](../../src/workbench/nest_tiles.h): the heaviest entries get tiles in proportion to their weights, entries whose share would fall under the minimum tile's area get that area and the larger ones share the rest, and only the entries whose tile could not meet the profile's minimum size, or could not leave room for the narrowest form of their name (measured with the semibold label metrics), fold into "+N more". The Iris hub keeps its note 2 px inside its border, taking away the count line and then the note's last lines (ending in an ellipsis) where it cannot fit; its readout names the entry with its measure and count as a whole trail at the line's right end. A flow pill whose name fits no cut is not drawn.

The shape under the pointer comes from `workbench::hitShape` over the shapes drawn now. The view reports hover changes, presses, activations (a left or middle button pressed and released over the same shape, with the modifiers held), context requests (a right press over a shape or the background), the wheel with its delta and position, and keys while it has focus, and it asks a provider for the hovered shape's tooltip. The owner sets the highlighted node another pane points at and the cursor's node; `marks()` hands the hovered shape and both nodes to the scene builders, and a change of any of them is reported so the owner restyles the scene.

The pixel tests draw through the real program into an offscreen framebuffer of an OpenGL ES 2 context created without any display server ([gl_test_context](../../tests/gl_test_context.h)), and skip with exit code 77 on a machine that offers none. Regressions: [shape batch render](../../tests/shape_batch_render_test.cpp) and [shape view](../../tests/shape_view_test.cpp).

Whole scenes are checked as pixels by [SceneCapture](../../tests/scene_capture.h). `RenderContext` cannot run in a test: `GlSharedContext::initialize` takes a `wl_display`, `RenderContext::renderScene` draws only into a `RenderTarget` made from a `wl_surface`, and its scene walk is private. The toolkit's drawing classes need nothing but a current context, so the rig creates the GLES backend, the Pango text renderer and the icon renderer on the offscreen context, arranges a root node with text measured at the requested scale, and walks the tree into a framebuffer of the scaled size the way `renderNode` does: transforms, opacity, z order, clipping, culling and proxies. Every rig's context terminates the EGL display they all share, so `SceneCapture::create` refuses a second rig while one is alive. Text is shaped and rasterized with the machine's fonts, so a test checks colors, positions and coverage rather than exact glyph pixels. [`test::writePng`](../../tests/png_writer.h) writes a capture for a person to look at: it writes a new file beside the target and renames it over the target, so a failed write leaves whatever was there untouched. The [scene capture test](../../tests/scene_capture_test.cpp) writes its own captures into the folder named by `LUCIOLE_CAPTURE_DIR`. The walk mirrors `RenderContext::renderNode` and must follow it when the toolkit changes.
