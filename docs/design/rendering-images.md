# Rendering and images

## Shared and application-owned code

`lib/` is a normal local copy of Noctalia's reusable library. Do not patch it in Luciole. Port generic fixes upstream before copying reviewed updates back; do not introduce a sibling include path, shell service or second renderer.

[library_setup.cpp](../../src/app/library_setup.cpp) supplies application identity, explicit asset roots, palette, UI strings and the Luciole image provider. Luciole selects its canonical environment/install asset root before library initialization. An invalid explicit root fails rather than silently searching elsewhere.

Luciole owns decoration negotiation, clipboard/drop transport, cursor fallback, browser composition and selection contours. Common widgets use the actual shared Button, Stepper, Select, Toggle, ScrollView and virtual-grid controls. A file-manager preference binding belongs here, while a generic widget correction belongs upstream.

The compositor's fractional-scale preference belongs to one Wayland surface. Output updates refresh the output scale seed without clearing that preference; subsequent preferred-scale events replace it. Destroying the Wayland surface clears the preference before the object can create another surface.

## UI phases

Preserve PrepareFrame → Update → Layout → Render.

- Update applies prepared state and publishes model/UI changes.
- Layout measures, mutates scene structure, binds visible cells and chooses physical image sizes.
- Render only paints prepared state. It performs no layout, traversal, filesystem I/O or decoding.

Callbacks schedule the required phase. They do not synchronously rebuild a scene from an arbitrary worker or input callback. Virtual cells release work when hidden, retired or rebound; bounded pooling must not retain every file in a large directory.

## Icon theme updates

Luciole owns icon selection and monitoring in `src/system/icon_resolver.*` and `icon_theme_poll_source.*`. Desktop GSettings selects the theme when its schema is available; GTK settings.ini provides a fallback. The main-loop watcher observes `changed::icon-theme`, reads the key after connecting, and debounces selection changes alongside existing artwork file watches. Accepted changes invalidate the application icon cache and rebind browser artwork. GSettings objects are optional when the schema is absent; observer teardown disconnects callbacks. The `icon-theme` suite uses private schemas/settings and artwork to exercise selection, fallback, live changes and file replacement.

Size-aware lookup first chooses artwork within the directory's declared Fixed, Threshold or Scalable range, then its closest nominal size. SVG beats PNG only at an otherwise equal size score. When no range matches, the existing preference for gentle downscaling over enlargement remains; the first theme with a matching name still owns the result. The size-free lookup retains its scalable/large-first order. Scoring skips filesystem checks for candidates that cannot improve the result. Selection and decoding remain on the existing workers, with physical-pixel cache keys and unchanged invalidation.

This respects the size-specific artwork described by the [Icon Theme Specification](https://specifications.freedesktop.org/icon-theme/latest/) and compared through native [GTK icon lookup](https://docs.gtk.org/gtk4/method.IconTheme.lookup_icon.html). Papirus makes the difference visible: its [96-pixel Places directory](https://github.com/PapirusDevelopmentTeam/papirus-icon-theme/blob/master/Papirus/96x96/places) links to the 48-pixel drawings, while its [128-pixel directory](https://github.com/PapirusDevelopmentTeam/papirus-icon-theme/blob/master/Papirus/128x128/places) links to the 64-pixel drawings. Selecting the latter at 96 pixels introduces fractional geometry and different padding despite both files being vectors. Lookup therefore considers size before format, ahead of physical-size rasterization.

Resolver instances retain a shared immutable search plan and per-instance result/missing caches. A published plan owns a cached immutable watch-path snapshot; callers may keep old snapshots safely across theme/content generations. Temporary hash sets deduplicate search/watch paths while ordered vectors retain first-match theme, inheritance and size precedence. Building a plan stats each search directory once: lookups skip directories that did not exist, and their modification times form the content signature, a 64-bit FNV-1a hash like the plan signature. A directory that appears later changes a watched ancestor and rebuilds the plan. Generation changes clear local results and acquire the new plan. IconThemePollSource schedules initial discovery, content/signature checks and watch construction through serial cancellable GTask work. The main context keeps the optional GSettings subscription, reads its key after connecting, receives inotify events and coalesces pending content/metadata flags with a 100 ms debounce. Its 60 s fallback check runs only while the watch set is missing or incomplete; a complete set wakes nothing while idle.

Watch replacement keeps the old set active while the worker constructs a new set. Named ancestor watches are installed first, including parents of linked or missing directories. A post-registration content validation covers edits before coverage existed: when icons were already looked up, the content generation is invalidated; when none were, comparing the rebuilt plan's signatures is enough and an unchanged theme keeps its generation. Changed paths trigger another construction pass. Completion drains the old queue before replacement and the new queue afterward, preserving further edits as pending work. Dropping old watch sets schedules their kernel-watch removal on a worker too. Closed sources disconnect settings, cancel work and reject late completions through weak lifetime ownership; teardown never joins a worker on the UI thread. Preserve actual filesystem path semantics around symlinks and `..`.

This removes synchronous watcher work from startup and normal dispatch, with extra validation/allocation costs. Full coverage and refresh completion can take longer, and measured CPU/PSS rise. Resolver plans remain immutable and shared, and image work still belongs to existing icon workers. This does not change file-listing storage or move scene/GPU mutation onto a worker.

## Thumbnail and preview pipeline

One application-wide [ThumbnailService](../../src/thumbnails/thumbnail_service.h) owns bounded generation requests, revisions, priority and cancellation for both browsing thumbnails and preview images: one memory budget, one decoder pool sized to a quarter of the CPUs (two to six helpers). Preview requests run first, then visible cells. Work nobody holds is cancelled. Released images stay resident until they go unseen for five minutes (thirty seconds for previews), so returning to a folder or scrolling back does not wait for the disk or a decoder; a held image counts as seen. A 256 MiB budget, charged each image's real decoded size, is only a safety cap that evicts the least recently used. Purpose is part of an image's identity, since previews accept no smaller foreign thumbnail and take clean video frames. [PreviewService](../../src/thumbnails/preview_service.h) requests preview content through it; the service's owner forwards change notifications to each page's preview. Their generation policy, freedesktop disk store and FFmpeg/Poppler providers remain Luciole-owned.

Thumbnail policy defaults to Local. It skips paths whose filesystem may go over a network, using the folder listing's network filesystem types. FUSE counts as network only without a disk device number (`major(st_dev) == 0`), so ntfs-3g on a disk stays local while rclone, sshfs and gocryptfs are skipped; a path whose filesystem cannot be read is skipped as well. All permits generation for regular files with an accessible filesystem path, including mounted network shares, without treating a remote/unknown filesystem flag as a generation ban. Locations with no filesystem path remain shared-cache-only; no whole-source remote download is introduced. Use the same held descriptor, identity/revision checks, cancellation and bounded worker/provider queue as for local files. Image/PDF sources retain the configured encoded-byte cap; seekable video/audio do not inherit that cap and remain subject to helper CPU, wall-time, memory, pixel and output bounds. Cache publication and source-change checks are unchanged.

Raster images use the [GdkPixbuf/Glycin adapter](../../src/imaging/pixbuf_image_decoder.cpp). Decoding/provider processes run outside Render with bounded input, pixels, memory and time. Helper memory is capped with `RLIMIT_DATA`, not `RLIMIT_AS`: Glycin's thread pools and allocator arenas reserve far more address space than they touch, and an address-space cap made large images fail at random. [thumbnail_worker.cpp](../../src/thumbnails/thumbnail_worker.cpp) and [provider_process.cpp](../../src/thumbnails/provider_process.cpp) enforce the helper protocol; [thumbnail_store.cpp](../../src/thumbnails/thumbnail_store.cpp) validates shared PNG cache entries. Dependencies and installed loader coverage belong in [PACKAGING.md](../../PACKAGING.md).

Shared-cache PNG metadata accepts `tEXt`, `zTXt` and `iTXt`, including Qt-compressed URI fields. Decompression is bounded to 128 KiB per value and 256 KiB total text, with the existing CRC, chunk, pixel and file-size checks retained. Browsing can reuse a valid smaller third-party cache class when a larger one is absent; high-resolution previews still require their requested size. Imported cached pixels and any baked-in decorations are left intact.

The shared cache has no Luciole-side index. A write publishes through a private temporary file renamed over the URI's spec path, replacing any older thumbnail for that URI, whichever application wrote it. After each batch (completions gathered for 250 ms, up to 64), one scan of the four size folders sums regular, user-owned, spec-named PNGs and removes the oldest by modification time until the configured byte budget holds. Clear Cache removes only PNGs whose Software label is Luciole.

Video generation probes duration, samples the keyframe nearest 10% (keyframe-only decoding avoids decoding every frame since the previous keyframe), and tries another position near one third when the first sample is almost entirely black. Short/unknown-duration clips and failed seeks retain a first-frame fallback, and genuinely dark clips remain valid. Probe and sample attempts share the existing eight-second video request budget; source descriptors and helper resource/protocol limits remain. `X-Luciole::VideoVersion` distinguishes the corrected sampling from Luciole’s older first-frame cache entries; only those old Luciole results need regeneration, while other thumbnailers’ cache images remain reusable.

[FileIcon](../../src/ui/browser/file_icon.h) holds shared-library prepared-image leases. Immutable RGBA and source/revision/size identities enter [SharedTextureCache](../../lib/render/core/shared_texture_cache.h). Dispatch owns GPU upload and switching; identical prepared requests share residency within an EGL group. Do not reinstate per-cell texture uploads or a second Luciole GPU cache.

Layout requests physical pixels, including display scale. Grid thumbnails cannot replace the larger preview request. Keep an already ready image visible until a higher-resolution replacement uploads, preserve aspect ratio, and retain source dimensions separately from decoded/output dimensions. Source revisions must invalidate same-size edits without flushing unrelated images.

Preview and Properties share [asynchronous metadata](../../src/thumbnails/preview_metadata.h). The preview presents essential content facts; Properties can expose technical and permission information. Selecting a single folder starts the shared [folder totals service](../../src/fs/folder_totals.h) once for that selection: the preview shows its size and its file and folder counts, a new selection supersedes the running walk, and a running walk never marks the page busy. Properties keeps the explicit inspection card with its Stop button and detailed partial-result notes.

The list view Size column walks bound folder rows through the same service family: [BrowserController](../../src/browser/browser_controller.h) runs at most two walks for the rows its enabled list adapter binds, refuses network filesystems on the worker with the same probe family as thumbnail reads, stays on each row's own filesystem so a nested mount is never traversed, and publishes each terminal result into a per-entry cache that also absorbs refusals, dropping entries when the listing republishes changed facts or retires the id. Rows show the finished size; “≥” marks partial results; refused network rows keep the cell blank; bounded progress never repaints rows and a walk never marks the page busy. Drive removal cancels its walks and drops cached sizes under the removed root alongside the thumbnail reads. Miller columns, grid captions, selection totals and Properties keep their existing behavior.

Native symlink metadata retains the no-follow query for the link's own facts and adds the literal stored target and filesystem-resolved absolute target on that same worker. Resolution preserves symlink/`..` ordering, reports missing/inaccessible/looping targets and never enumerates the target. The link's inode and change revision are rechecked before publishing; cancellation and superseded-request guards remain. Resolution is observational, with no target lease or live target monitoring. Opening links uses a separate following type query; native `stat` errors and a provider's unresolved symlink type prevent default-handler dispatch. Permission and transfer services keep their existing no-follow policies.

This follows [Nautilus 49's single-link Properties field](https://raw.githubusercontent.com/GNOME/nautilus/gnome-49/src/nautilus-properties-window.c), inspected as a primary-source comparison. Luciole additionally separates the stored target from the final native path. [GIO documents](https://docs.gtk.org/gio/method.File.query_info.html) that a following query can still return the link itself when its target does not exist; opening must handle that result explicitly. No live comparison or broader remote-target metadata support is claimed.

## Shared video decoration

Browsing requests send their selected video frame through the system `ffmpegthumbnailer -f` filter, matching its standard desktop thumbnailer entry. The input is a private PNG re-encoded from validated pixels, passed by descriptor, rather than the original media. This preserves Luciole’s representative-frame selection and source pixel/protocol limits. Decoration runs on the existing worker, with one CPU, at most two seconds and the remainder of the same eight-second video budget. Validate the resulting PNG and require unchanged dimensions. Missing/failed/timed-out helpers retain the selected plain frame; cancellation still prevents publication.

The decorated pixels are stored in the existing shared cache, so other file managers see the same border. The sampling/style version is `3`; older Luciole video cache entries refresh, while foreign entries remain reusable and protected. Native video preview requests skip the shared video cache, generate a clean frame and retain it in the memory cache under the preview purpose. They must not overwrite the browsing thumbnail. Non-native/cache-only previews can only use existing cache content, including any baked-in decoration. This is an application-owned adapter for ffmpegthumbnailer, not a general `.thumbnailer` discovery implementation or an icon-theme overlay.

See [PACKAGING.md](../../PACKAGING.md#runtime-integration-and-helpers) for runtime helper dependencies.

## File type detection

Directory listings and recursive filename search request GIO’s `standard::content-type` and `standard::fast-content-type` in their existing cancellable asynchronous batches. Worker-backed single-file details query both attributes too. The shared reader in [file_metadata.cpp](../../src/fs/file_metadata.cpp) prefers a valid regular type and uses the filename-only fast type when the provider omits or returns an invalid regular attribute. A valid `application/octet-stream` result remains authoritative. GIO can inspect content when a filename is insufficient, so extensionless text, dotfiles such as `.bash_history` and extensionless images do not depend on filename guesses alone.

The resulting DirectoryEntry type drives icons, list type labels, preview selection and the Properties MIME field. File-tooltip details use the same provider policy through the worker query. Do not add filename-specific MIME overrides or move queries into layout/render callbacks. Retain no-follow-symlink flags; regular and special file handling belongs to GIO. This uses existing GIO and shared MIME data, with no decoder or packaging dependency changes.

## Colored text

The library's text path rasterizes a label as coverage and tints it with one color, so formatted text is drawn by Luciole into RGBA tiles instead.

[styled_text.h](../../src/formats/styled_text.h) turns a file's text and [FileKind](../../src/formats/file_kind.h) into a `StyledDocument`: blocks of lines of runs, each run carrying a style role (keyword, string, comment, key, heading, emphasis, inline code, link and so on). Markdown becomes headings, paragraphs, list items with their markers, quotes with their depth, framed code blocks colored by their fence language, tables with column alignment, and rules. JSON is printed with two-space indentation; invalid JSON is shown raw with the reason. JSON cut at the byte limit cannot parse, so it is colored line by line as it stands and reports no problem. Plain text meant to be read (`FileKind::prose`: .txt and .text files, README, LICENSE, CHANGELOG and similar names, and text the loader finds by its bytes) is one prose block of the file's own lines; a line longer than 4,096 code points is split after a space, or inside a word longer than that, into lines of at most that length, so that no layout holds an unbounded paragraph. Every other kind is one code block colored by its tokenizer. Color codes give swatches, each a color and the column it sits before, following the color scanner's rule for which kinds have colors, with color names only in CSS and SCSS. The builder reads at most 256 KiB and 2,000 lines by default, and cuts code lines and table cells at 2,000 characters; prose wraps, so a Markdown paragraph is bounded only by the byte limit and the Markdown parser's own limits, and a plain text paragraph by the segment length. It reports each cut in its own flag, replaces invalid UTF-8 with U+FFFD and shows ASCII control characters as their Control Pictures symbols. It uses the standard library only.

[TextTileLayout](../../src/imaging/text_tile_renderer.h) lays a document out with Pango once per width, pixel scale and theme, and draws any band of rows into a premultiplied RGBA tile of 256 device pixels with Cairo. Code lines use the monospace family without wrapping and widen the layout up to 4,096 device pixels; a longer line is clipped and ends in a mark. Prose wraps at the requested width in the interface family, at word boundaries and inside a word wider than the width, each line being one Pango layout that is made again for every tile it crosses, headings are bold and never larger than the text, so a preview stays below the list's size, list markers sit left of their item, quotes get bars, code blocks get their own background and tables are drawn as grids. Each list nesting level indents its item text past the widest marker drawn at that level, so long numbers stay inside the padding and items of one list stay aligned. Table columns narrow to fit the requested width, each keeping its share of the width above its narrowest; a table that needs more even at its narrowest widens the layout as code does, and past 4,096 pixels its last columns are cut and `truncated()` says so. A swatch is a square of about 0.8 em with a thin border, over a checkerboard when the color is translucent, in a gap the layout keeps before the color code; document columns do not count the gap. Colors come from a `TextTileTheme` the caller fills from the palette, one per style role plus background, code background, outline and checker colors. A layout's height stops at 512 tiles and at 2^28 pixels of width times height, and `truncated()` reports the cut. The layout also answers the box of a line and column and the line and column at a point.

Layout measures every line once and keeps only geometry; a tile shapes again only the lines it crosses. A layout owns a private Pango font map and context, so it must stay on one thread at a time, while separate layouts render on separate threads concurrently. Shaping and drawing are work for a worker thread, never for Render. The [styled text](../../tests/formats_styled_text_test.cpp) and [text tile](../../tests/text_tile_renderer_test.cpp) suites draw into memory and read the pixels back.

[TextLineStrip](../../src/imaging/text_line_strip.h) draws one code line at a time in the fonts, theme colors, tab stops and swatch gaps of a text tile's code lines, through the same line layout code, so a strip equals that line cut out of a tile. Every line gets the height and baseline of the code font; a glyph from a taller fallback face does not move it. `render` returns any window of a line up to 4,096 device pixels wide as premultiplied RGBA, transparent where nothing is drawn, with an optional underline under columns an input method is composing; the caller paints the background. Only the glyphs whose ink reaches the window are drawn, on a scratch surface that holds all of their ink: Cairo trims a glyph run that overflows its surface to the glyphs' metric boxes, which cuts the top row of hinted ascenders. `caretX` and `columnAt` convert between columns and device pixels from the line's start; a swatch's gap belongs to its color code and grapheme clusters stay whole. A line is shaped only up to the columns Pango's 32-bit positions can place. The strip keeps the shaped layout of the last line it was asked about, so repeated questions about one line do not shape it again. Like a tile layout, it owns its font map and stays on one thread. The [strip](../../tests/text_line_strip_test.cpp) and [strip pixel](../../tests/text_line_strip_pixels_test.cpp) suites compare strips with tiles and check carets, windows and limits.

[text_document_loader.h](../../src/imaging/text_document_loader.h) turns a file into a document off the main context. It reads at most 256 KiB through `startUserFileRead`, then on a worker refuses private key material before anything else, takes the kind from the name, then from the content type, then from the bytes (valid UTF-8 whose only control characters are tabs, line breaks, form feeds and escapes is plain text), and builds the styled document. A read cut at its limit drops an incomplete last character or a lone final CR before `textFacts` takes the encoding and line endings. The result carries the document, the facts (bytes and lines read, encoding, line endings, whether it was cut), the file identity of the read for a later save, and one state: shown in full, cut, not text, private key, unreadable, or changed while reading. A file of a non-text kind, or text that holds a NUL byte, is not text and comes as a [hex dump](../../src/formats/hex_dump.h): rows of sixteen bytes with an offset, the bytes in hex in two groups of eight and the printable characters, at most 64 KiB.

[TextTileService](../../src/imaging/text_tile_service.h) owns one worker thread and every layout on it. A view opens a document with its options and keeps the handle; it asks for tiles by index, and the layout's size and each tile reach the default main context through an idle source. A newer request of a document replaces its queued tiles, a relayout starts a new revision and drops what was queued for the old one, and closing the handle drops its work and frees its layout on the worker. Results of a closed document or of an older revision are never delivered. A request takes at most 64 tiles, a document queues at most one layout, the most recently asked document is served first, and the worker stops drawing while four results wait for the main context. It sleeps while nothing is queued.

[TextTileView](../../src/ui/controls/text_tile_view.h) shows the tiles as image nodes in a clipped area with the toolkit's vertical and horizontal scrollbars and the wheel. The owner calls `update()` once per frame, which asks for tiles, uploads at most two that arrived and starts layouts; layout only places nodes. The tiles crossing the viewport always hold textures, and one more below and one above join them while all of them fit a byte budget, 32 MiB by default; nothing else does. Hiding the view releases its textures, its layout on the worker and its timer, and destroying it does the same; shown again, it lays the document out at the same scroll position. Plain code is laid out at its own width and scrolls sideways; a document with prose, tables, rules or framed code wraps to the view's width. When the width or the text size of wrapped text changes, the line at the top of the view, a paragraph being one line, stays at the top and the top keeps its fraction of that line's height. The renderer's 8-pixel margin after the last column and line scrolls only along with text that does not fit, so a bar shows only when some text is out of sight. A hex dump takes 16, 12 or 8 bytes a row, the most whose rows fit the width: the character width comes from the dump's own layout, and when the width or text size calls for other rows, `hexDumpAgain` reads the bytes back from the rows and dumps them again on a worker, and the new dump takes the old one's place with the same bytes in view, once the visible tiles of the old layout are in, since closing the old document drops the tiles it was asked for. A new width, pixel scale, palette or text size lays the document out again after 120 ms, and the old tiles stay on screen until the new ones cover the viewport; meanwhile the new tiles that arrived are kept only while they lie in or next to the viewport. [text_tile_view_style.h](../../src/ui/controls/text_tile_view_style.h) maps the style roles to palette roles over SurfaceContainerLow; the owner sets the text size and code is drawn at 0.95 of it. Hovering a swatch shows its color as `#rrggbb`, or `#rrggbbaa` when it is translucent. Loading, an empty file, refusals and failures are said in words, and cut text and hex dumps get a caption above the text that says how much is shown. The [loader](../../tests/text_document_loader_test.cpp), [service](../../tests/text_tile_service_test.cpp), [view](../../tests/text_tile_view_test.cpp), [view reflow](../../tests/text_tile_view_reflow_test.cpp) and [view pixels](../../tests/text_tile_view_pixels_test.cpp) suites run against real files, a real worker and an offscreen framebuffer.

## Font previews

Font types (`font/ttf`, `font/otf`, `font/collection`, `font/woff`, `font/woff2` and their aliases) get a sample sheet and facts. The `.otf` and `.otc` globs also name ODF templates, so those two template types are routed as well and the file's signature decides. [font_facts.cpp](../../src/thumbnails/font_facts.cpp) accepts sfnt files with TrueType or CFF outlines, collections, WOFF and WOFF2, and checks that every table the directory lists lies inside the file before FreeType reads it.

Both run in the resource-limited helper. The sheet comes from `--font-preview-worker` in [font_preview.cpp](../../src/thumbnails/font_preview.cpp), started by the thumbnail provider like the image worker and answering in the same private RGBA protocol. The helper makes an empty fontconfig configuration current, so neither the default configuration nor the user's font settings load, then adds only the source file to a private configuration bound to its own Pango font map. Samples use the file's own glyphs and nothing reaches the interface's fonts. Both helpers read at most `fontByteCap`: the preview size limit, never more than 256 MiB (`kMaxFontFileBytes`), so a font gets both its sheet and its facts or neither. Strike-only faces such as color emoji have their bitmap size removed from the private patterns, so cairo scales them to the requested size.

The sheet is the requested width and at most as tall, laid out in units of 1/320 of its width so it keeps its proportions at every size and pixel scale: the family and style name when the face covers it, a sample at 12, 18, 24, 36 and 48 units, digits, then the names of the next three faces of a collection. [font_sample.cpp](../../src/thumbnails/font_sample.cpp) picks the text from the face's coverage: Pango's sample sentence for the first script the font covers when every character is present, otherwise that script's first covered letters. Symbol fonts and fonts that cover no script show a grid of their first 48 drawable characters. Right-to-left samples end at the right margin. Text is drawn in the theme's on-surface color over its surface color. The service reads both when it creates the request and keeps them in the image's identity (`fontSheetVariant`), so selecting the file after a theme change draws a new sheet. Font sheets are previews only and never enter or come from the shared thumbnail cache.

Facts come from `--preview-metadata-worker` given a font type: family, style, full name, version, format, glyph count, number of faces, variable axes with their ranges, monospacing, color glyphs and covered scripts, counted from the character map against a fixed table of script letter ranges. A damaged, empty or non-font file gives an error and the preview keeps the type icon. The [font facts](../../tests/font_facts_test.cpp) and [font preview](../../tests/font_preview_test.cpp) suites use public fonts found through fontconfig and report each kind the machine lacks.

## 3D models

STL, OBJ, PLY and glTF files (`.gltf` and `.glb`) are read by the mesh readers in [src/formats](../../src/formats/mesh.h), which run only inside the resource-limited helper. [loadMeshPreview](../../src/thumbnails/mesh_preview.h) blocks, so it runs on a worker: it opens a local regular file of at most 256 MiB, picks the reader from the extension and starts `--mesh-preview-worker` with the file as descriptor 3, one CPU and an output limit sized for the largest allowed answer. The helper reads with `kMeshPreviewLimits`: three million vertices and one million triangles, enough for a million triangles that share no corners, as in STL. A glTF file's outside buffers are opened only in the file's own folder, by a name without a slash, without following symlinks, and the file and its buffers share the 256 MiB cap. A reader's refusal reaches the user as one sentence by format, "This file is damaged or is not an STL model.", or, when a glTF buffer could not be read, as a sentence that says the model needs a file beside it; the reader's own words stay in the helper.

The helper answers in a private versioned format: `NMR1`, flags (normals present, cut by a limit, and the glTF parts that were skipped), the vertex and index counts, the bounds, then positions, normals and indices; or `NME1` and a printable message. The parent checks the counts against the answer's length and its own limits before it allocates, then that every value is finite, every position lies inside the bounds and every index names a vertex. Bounds past 10^15 in any coordinate (`kMaxMeshCoordinate`) give an error, which keeps the camera's single-precision matrices finite. It packs each vertex into 16 bytes, the position and a normal scaled to signed bytes; a mesh without normals gets one normal per triangle on three vertices of its own, so it is lit flat. STL models are turned Z-up, the other formats Y-up.

[MeshView](../../src/ui/controls/mesh_view.h) draws through [MeshProgram](../../src/ui/controls/mesh_program.h), a render extension. The model is drawn with depth testing into a texture of the view's size in buffer pixels with a depth renderbuffer, on a transparent background, and the frame shows that texture. It is drawn again only when the geometry, the camera, the size, the scale or the palette changes, so a still model costs one textured quad per frame and nothing between frames. The framebuffer object exists only during that drawing, since framebuffers are not shared between contexts; the texture, the depth buffer and the vertex and index buffers are kept until the owner calls `release`, the view is destroyed or the program is torn down. Every piece of GL state the drawing changes is restored. Where the driver lacks 32-bit indices, the mesh is split into parts of at most 65,536 vertices with 16-bit indices.

The camera fits the sphere around the bounds into the view with a 35 degree vertical field of view; a view narrower than 1:10,000 or wider than 10,000:1 is fitted as that ratio. Dragging with the left button turns the model around its up axis and tilts it, the wheel zooms between a quarter and eight times, and the button in the top right corner returns to the first view. Two lights fixed to the camera take their colors from the palette: the key light from the upper left in the primary color, which also gives the shadowed faces their base, and the fill light from the right in the tertiary color. Faces seen from behind are lit like their front, so open and inconsistently wound meshes read correctly.

The [mesh preview](../../tests/mesh_preview_test.cpp) suite runs the helper on files of each format and feeds the parent hostile answers; the [mesh geometry](../../tests/mesh_geometry_test.cpp) suite checks the split into 16-bit parts and the camera at its limits; the [mesh program](../../tests/mesh_program_test.cpp) and [mesh view](../../tests/mesh_view_test.cpp) suites draw into an offscreen context and read the pixels back.

## Animated images

[AnimationFrames](../../src/imaging/animation_frames.h) decodes animated GIF, APNG and animated WebP through Glycin, whose loaders run each file in their own sandboxed process (bubblewrap outside Flatpak); the interface process receives finished frames and never decodes image data itself. On a worker it first reads the file's first 64 KiB: a PNG with no `acTL` chunk before its first `IDAT`, and a WebP that is a simple file or whose `VP8X` header lacks the animation flag, are answered still at once, without starting a loader. Any other file is opened, up to four frames are read, and a file with one frame is still. Still and failed files are left to the caller. Frames come from the loader as premultiplied RGBA, are averaged down to fit the requested box in device pixels, never above the image's own size, and are handed out with straight alpha. `animationFrameSize` gives that size: when rounding would put a frame over a quarter of the budget, its longer side gives way. A frame whose delay is 10 ms or less shows for 100 ms, as in browsers; longer delays are capped at ten minutes.

The loop count is read from the same 64 KiB by [bounded walks](../../src/imaging/animation_head.h) over the file's blocks: the GIF NETSCAPE2.0 extension counts repeats after the first play and a GIF without it plays once, APNG takes `num_plays` from `acTL`, WebP the loop count from `ANIM`, and 0 plays forever.

Decoded frames are bounded by a byte budget, 64 MiB by default, that includes the frame on screen. A play that fits is kept whole: it is read four frames per step, each step publishing its frames as soon as they are read, and decoding stops at the end of the play. A longer play streams: three frames are decoded ahead of the one shown, and the file is opened again at the end of each play. Each play reads at most 5,000 frames, and every frame stays within the shared 8,192-pixel side and 16-megapixel limits. An error before the first frame fails the file with a one-line message. An error or a cut file later in a play ends the play at its last whole frame and the animation loops over the frames it has. A file whose size changes between plays ends with the frames already decoded. Each decoding step is a background job that holds the decoder alone, checks cancellation between frames and publishes nothing once its owner is gone; nothing decodes while no frame is wanted.

[AnimatedImageView](../../src/ui/controls/animated_image_view.h) asks for frames at its laid-out size in device pixels. Layout only arranges the image and starts a timer: decoding begins from that timer, and a resized box decodes again only when the frame size `animationFrameSize` gives for it is a quarter larger or less than half as large as the frames it has, once the size has held for 150 ms. A toolkit timer shows the frame the view's clock says; a late tick skips frames to keep time, up to 64 at once, and a frame that is still decoding is shown as soon as it arrives. Each frame replaces the texture's pixels in place and marks paint dirty, so playing runs no layout. The image is centered in the box and keeps its aspect, never drawn larger than its own size in logical pixels. A click pauses and resumes, and the paused frame keeps its remaining time. `setShown(false)`, an invisible ancestor noticed at the next frame, or destruction stops the timer, ends decoding and frees the texture; shown again, the animation plays from the start. Still and failed files show nothing here and are reported through `onStateChanged`, which runs on the main context; the owner may destroy the view from it.

The [animation frames](../../tests/animation_frames_test.cpp) suite builds small GIF, APNG, PNG and WebP files of flat colors and checks frames, delays, plays, still files answered from their first bytes, scaling, the budget, the steps a play arrives in and broken input. The [animated image view](../../tests/animated_image_view_test.cpp) suite draws the view offscreen at chosen clock times, drives clicks through the input dispatcher, and measures processor time while playing and while hidden.

## Media

The optional `src/media` module plays video and audio files and reads their facts. The `media` build option chooses its sources: with GStreamer found, [media_player_gstreamer.cpp](../../src/media/media_player_gstreamer.cpp), [gstreamer_pipeline.cpp](../../src/media/gstreamer_pipeline.cpp), [frame_sink.cpp](../../src/media/frame_sink.cpp), [audio_tap.cpp](../../src/media/audio_tap.cpp), [gstreamer_runtime.cpp](../../src/media/gstreamer_runtime.cpp), [media_probe_gstreamer.cpp](../../src/media/media_probe_gstreamer.cpp) and [pipeline_thread.cpp](../../src/media/pipeline_thread.cpp); without it, [media_player_none.cpp](../../src/media/media_player_none.cpp), whose player fails every file with "Playback is not available in this build.", and [media_probe_none.cpp](../../src/media/media_probe_none.cpp), whose probe reads nothing. [MediaPlayer](../../src/media/media_player.h) and [MediaProbe](../../src/media/media_probe.h) name no GStreamer type, so callers build the same either way. Playback decodes inside the interface process, so `MediaView` decodes nothing until the user presses Play.

One pipeline thread builds every pipeline, applies state changes and seeks, and stops and frees pipelines, in order; after freeing one it trims the heap, since GStreamer's streaming threads free into heaps of their own. At process exit it finishes the queued jobs for at most a second and is then left behind, so a job blocked on a hung mount never keeps the process from ending. The main context never waits on GStreamer or on the disk: player calls store a request under the pipeline's lock and post at most one sync, which applies the latest target state, seek, volume, mute and frame size, and sets the state only when it differs from the one last asked. A paused pipeline whose frame size changed asks the player to decode the shown frame again, and the player does that as a seek of its own, so it waits behind a seek in flight and every done message the player hears is one it asked for. State, duration and errors reach the default main context through the bus watch, and frame notices and failures through sources of the same default priority, so a busy bus never holds them back; a closed player hears nothing more. The pipeline is `playbin` with video, audio and software volume only: no subtitles and no visualizations. Starting GStreamer lowers every decoder whose class says it runs on a graphics device below automatic choice, so a preview decodes on the processor and never sets up a graphics decoding context. Only absolute local paths are opened. Before building a pipeline the thread reads the path's status, and anything but a regular file, such as a FIFO or a device, ends in an error without being opened. An element whose class says it reaches the network or fetches adaptive streams is refused, so a playlist on disk ends in an error without a connection. Audio goes to the system's default output, opened before the pipeline is built, or to a sink that keeps the clock and plays nothing, which the tests use. When the system's output does not open, the player says so: a video plays silent, and a file with sound only ends in the error "This file cannot be played: no sound device was found."

Video goes through `videoconvertscale` and a caps filter into an `appsink` that queues one buffer, drops older ones and keeps no last sample of its own. A probe reads each stream's size and pixel aspect and sets the filter to the box the view asked for: the shown aspect is kept, frames are never larger than the source and never above 4,096 pixels a side. A new box while paused decodes the shown frame again at the new size, once the pipeline has settled. The streaming thread keeps only the newest sample and posts one notice until it is taken. `takeFrame` maps that sample and hands out its RGBA rows without copying them; the frame holds the sample until it is dropped. Audio-only files have no frames.

The audio tap hands a visual the sound being heard. `startAudioTap(rate, length)` takes a rate of 1,000 to 192,000 samples a second and a window of 1 to `rate` samples, and stays on across files until `stopAudioTap`. While it is on, a pad probe sees each buffer and event on the streaming thread at the output of an `identity` element named `sound-tap`, which the pipeline gives `playbin` as its audio filter, so it lies ahead of the software volume and volume and mute never reach it; while it is off, the probe is removed, so nothing is converted or kept. The probe is put on and taken off by the pipeline thread through the same sync as the other requests, so switching it while playing never touches the sound: the sink plays the same samples, with the same timing, either way. The probe converts each buffer with GStreamer's audio converter to mono 32-bit float at the asked rate, a fiftieth of a second of input at a time, drops the resampler's leading output, and writes the result under a short lock into a ring of three seconds of samples allocated for each open file while the tap is on. The filter sits after the player's audio queue of one second, so its samples arrive up to about 1.3 seconds before they are heard; the ring keeps them until then. Each run of samples is placed at the stream time of the buffer it came from, and starts again after a flush, a new segment, new caps or a jump of more than 20 ms. `copyAudioWindow` asks the pipeline for the position being heard and copies the newest `length` samples that end there, oldest first, to the start of the caller's buffer, with their count and whether they moved since the last copy. Because the window follows the sink's clock, a decoder that runs ahead and an output that takes its sound early do not move it ahead. Paused, the position stands still, so the window does too and is not fresh; after a seek the old samples are gone and the window fills again from the new place. A tap turned on while playing gets its first window once the sound that passed it after that moment is heard, the audio queue and the output's own buffer later, about a second and a half. The samples come before the volume, so a muted or quiet file still gives them at the file's own level. With no sound device a file with sound only ends in an error, so the tap has nothing to give there. Closing the player, or opening another file, frees the tap's ring with the pipeline.

Bink 2 video plays through the same `playbin` and the same `MediaPlayer`: [bink2_demux.cpp](../../src/media/bink2_demux.cpp) registers, from `startProblem`, a statically registered plugin with a typefinder for the signature `KB2` followed by a revision from `f` to `n`, and a demuxer element, `luciolebink2demux`, of rank primary plus one, that `playbin`, `parsebin` and the probe pick like any other demuxer. The element reads the file in pull mode from `filesrc`, so a Bink 2 file must be a seekable local file, and decodes it itself: it exposes `video_0` as raw I420 and `audio_N` as raw S16LE for each sound track, no decoder follows it, and it names no network class, so the network refusal is unchanged. The decoder is a pinned copy of libbink2 in `subprojects/libbink2` (LGPL, built only with playback; its changes are listed in its README), wrapped by [Stream](../../src/media/bink2_stream.h). `Stream::open` reads the 44-byte header through the read function before the library allocates anything and refuses, with a sentence the player shows, what is not Bink 2, a revision outside `f` to `n`, a side above `kMaxMediaFrameSide`, an alpha plane, zero or more than a million frames, no frame rate, more than seven tracks, and a rate outside 1,000 to 192,000. The frame index and the sound index are read at open, so the file's key frames and the samples of each frame are known; a frame packet above 64 MiB is refused. [SlicePool](../../src/media/bink2_slice_pool.h) holds four worker threads, started with the stream and joined when it is freed. A frame holds four slices (eight at most), each decoded by one thread into the planes of the picture with row buffers of its own; the slices of a frame never read each other's pixels, so the picture is the same bit for bit as with one thread, which `bink2_stream_test` checks against the library's own whole-frame decoder: 40 frames from the start and 40 after a key frame in the middle, plane for plane. The planes of a picture are one buffer of a pool of at most eight, which the element hands downstream with a video meta that gives the decoder's strides, so a picture is written once, by the decoder, and read by the converter; the picture before it, held as the reference of the next, is the previous buffer. The decoder rounds chroma motion compensation once, as the reference decoder does, and the caps say full range and the BT.601 matrix, which is what the library's own conversion uses and the decoders' sources are silent on beyond that; transfer and primaries are unknown, since nothing states them.

The element's streaming task decodes and pushes one frame, or one frame's sound, a pass, so a seek takes the stream lock between two passes. A flushing seek by time, forward at normal speed, is the only one it takes; a segment seek, a trick mode, another rate or format is refused. It ends the old streaming at once (flush start goes down the pads and to the file, the buffer pool stops handing out buffers), finds the frame, and starts again: an exact seek decodes forward from the key frame at or before the frame without handing the pictures on and hands on the frame the time falls in, with the segment starting on that frame's time; a key frame seek lands on the key frame the flags and the distance pick (`SNAP_NEAREST` the nearer, ties before); in a file without sound, a seek to the frame already shown hands that picture on again without decoding, and a seek forward within the same run of frames goes on from the held picture. Every pass is short, so a seek in the middle of a long decode forward is answered after the frame in hand. Sound runs ahead of the picture: the first frame of a file with sound can hold a large part of a second of it, and each chunk states how many bytes it decodes to, the last chunk less than its block. The element counts the samples of every frame from those sizes when it opens, stamps a block with the number of samples before it, and cuts the last block to the stated size, so the sound is gap free and ends with the picture. After a seek it decodes the sound from two frames before the frame that holds the time, handing on only what ends after it, so the sound comes back at the right place, bit for bit what a file played through gives; a track whose sound ended is closed with its own end of stream, so a sink waiting for it prerolls. Exact seeks and loops start the decoder over from a key frame, so an exact seek costs the decoding of the frames between the key frame and the target.

A Bink 2 poster, for the preview and for list thumbnails, comes from the same `renderThumbnailProvider` call as any video's, which branches on the file's own first four bytes when the type is `video/`, where `thumbnailContentType` counts a file the system types only as plain bytes, or not at all, as a video when the app's name table says so (`bik` and `bk2` on a system whose MIME database has no globs for them), the same table the preview kind uses and runs the helper like the other providers: `/proc/self/exe --bink2-poster-worker SIDE OUTPUT` through `runProviderProcess`, with the same sandbox, resource limits, eight-second limit and cancel path (cancelling kills the child), the file as descriptor 3, and two CPUs. A browsing process therefore never decodes a file it was not asked to play; only Play does that, in the process, like every other GStreamer decoder. The helper is a mode of the application binary, as the image, font, mesh, sheet and metadata workers are, so there is no new installed file and nothing to locate: a copied binary or a test program that dispatches the mode (the tests call `runBink2PosterWorker` first in `main`) is its own helper. `thumbnails` does not depend on `media`; the application's `cli.cpp` dispatches the mode to [runBink2PosterWorker](../../src/media/bink2_poster.h). The helper starts no GStreamer, writes only its output file, creates it new, and answers in the thumbnail workers' private result: the size and RGBA rows, or a reason on one line, which it also prints on stderr with exit status 1. Without playback in the build it only fails. The other path asks for a frame at a tenth of the duration, then a third, then the first key frame, and keeps the first that is not black (98 percent of pixels under 12 in every channel), else the first black one it got. The Bink 2 poster decodes from the start, at most `kPosterFrames` (30) frames, since later frames need the ones before them, and keeps the first frame whose sampled luma is not black by the same 98 percent rule, else the brightest of the 30. It applies the header checks and limits of playback, reads with `pread` only, and returns any failure, damage in those frames included, as the reason the service logs with the type and size, so the result is the path's usual "no poster". The frame is averaged down to fit the side, never enlarged, and converted as the player's caps say. List thumbnails come from the same call; they lack the filmstrip frame the helper draws on other videos' thumbnails.

A seek that stays in flight for `MediaView::kSeekNoticeDelay` (300 ms) puts "Seeking..." in the control bar's message label beside the time, in the secondary text color. `MediaPlayer::seeking()` is the player's own in-flight flag, the one that holds later seeks back; the view starts a 100 ms watch timer at each seek it asks for, which restarts the wait and clears the note, and the watch stops and clears it when the flag drops, the player fails or the view stops. A seek that settles sooner shows nothing. An error replaces the note, and the note replaces the no-sound-device note while it shows.

[MediaProbe](../../src/media/media_probe.h) reads a file's playing time, whether it has video and sound, and the first video stream's picture size, on a probe thread of its own so a slow file never holds up playback. It treats the file as hostile: only an absolute path to a regular file is opened, the network refusal above applies, and the pipeline is `filesrc` into `parsebin`, which demuxes and parses without decoding. `parsebin` exposes every stream before the first buffer flows, and a stream that goes through a parser, such as MPEG-4 video, MP3 or FLAC, gets its complete caps only just before its first buffer, so each stream's kind and picture size are read when its first buffer, gap or end passes. Buffers are dropped rather than held, so one stream never stops the demuxer before the others reach theirs, and after 128 buffers every stream stops, so no more of the file is read. Those buffers also let a parser estimate a playing time its container does not state, as in an MP3 without a header that gives it. The read ends once every stream is known and the playing time is known, estimated or every stream ended, or at an error, on cancellation or after three seconds; a size or time past what can be believed is left out. A read that was cancelled while it waited for the thread opens nothing. The result reaches the main context once, unless the read was cancelled, replaced or its probe destroyed.

[MediaView](../../src/ui/controls/media_view.h) shows the poster its owner gives it until Play, then the frames, with a Play and Pause button, elapsed time, a [position bar](../../src/ui/controls/media_position_bar.h), total time and Mute. While shown it reads the file's facts with a probe, so the total time and its `facts()` are known before Play; `onFactsChanged` tells the owner, and the column preview puts the playing time and picture size in its facts line. A file with sound only and no poster shows a large sound glyph in the middle of the stage; the owner's cover replaces it. While such a file plays, or is paused after playing, its visual covers the stage instead unless the visualizer is off, and two buttons beside Mute turn the visualizer on and off and step through the visuals. A loop button beside Mute, for video and sound, sets the player's loop switch, which the view keeps across files; below the width where the row, the loop button and a position bar of 24 pixels fit with the times, the elapsed and total time are hidden together, and below the width where they still do not fit without the times, the visual button of a sound file is hidden too (the visualizer button, loop, Mute and Play stay); each choice is measured with the others set, never from the last result, so a wider row brings them back. The player restarts a looped file with an exact seek to the start when its end arrives and keeps the state Playing; a length that is not known, a refused seek, or an end less than `kMinLoopPass` (100 ms) after the last restart with no seek or Play between, ends the file as without loop. The column preview passes the saved `workbench_media_loop` into every media load and on to a playing one, and the page saves what the button reports. A click on the picture toggles playback and takes the keyboard: Space toggles, Left and Right seek five seconds. A press on the bar seeks, a drag seeks to the nearest key frame as it moves and the release seeks exactly; a drag whose pointer capture is cancelled, as when the pointer leaves the window, seeks exactly where it last was. A frame notice schedules one zero-delay timer that takes the newest frame and replaces the texture's pixels in place, so playback runs no layout and copies each frame once, into the texture. While playing, a repeating timer moves the bar and the elapsed time four times a second; paused, ended or stopped, no timer runs and the view costs nothing. Layout only places the picture, the glyph and the controls and records the stage's size in device pixels, which the next timer turn passes to the player. With no sound device, the note "No sound device was found." sits beside the time in place of Mute for that playback, and a sound file shows its error. `setShown(false)`, a hidden ancestor noticed at the next timer turn, a new source or destruction stops playback, frees the pipeline on the pipeline thread and releases the frame texture; hiding also drops a facts read and releases the poster's texture. The owner sets the text size.

[AudioVisualView](../../src/ui/controls/audio_visual_view.h) is that stage of a sound file: the sound glyph, or one of the nine visuals behind [AudioVisual](../../src/ui/controls/audio_visual.h), which [makeAudioVisual](../../src/ui/controls/audio_visual_factory.cpp) creates by kind. The media view tells it its player and whether the file has sound only after every change of either and of the player's state. The tap is on, at 22,050 samples a second with a window of 2,048, while the visualizer is on and a sound file is open, from loading until it ends; the visual, its [AudioAnalysis](../../src/workbench/audio_analysis.h) and the sample buffer exist only while the view is active, playing or paused after playing. In each frame the surface draws while the file plays, the node copies the window heard now, analyzes it with the seconds since its last frame, gives the frame the player's position as its playing time, advances the visual once and draws it over the column preview's fill into its box in buffer pixels, with Primary, Secondary and Tertiary as accents, SurfaceContainerLow as background and OnSurface as text; a zero-delay timer then marks it for the next frame, which the surface draws at the compositor's pace, so nothing runs ahead of the display. Paused, a redraw for another reason draws the same picture and asks for nothing. Off, hidden, ended or without a player it holds no tap, no visual, no GL objects and no timer: it frees the visual's GL objects with the context made current, and after a lost context the visual forgets them and makes them again on its next draw. A visual whose program does not compile logs the error and leaves the stage empty. The visualizer button and the visual button, which steps back with Shift as read from a modifiers function the owner gives, apply the new choice at once and report it through `onChosen`. In the column preview, [WorkbenchPreview](../../src/app/page/workbench_preview.h) passes the page's choice into every media load and on to a playing one, and the page saves what the buttons report as `workbench_audio_visualizer` and `workbench_audio_visual`, so the buttons and Settings → Views → Workbench always agree. The visuals upload at most a few kilobytes a frame: one row of a 64-texel texture for Halo, Eclipse and Dark Sun, one row of a history texture of 128 texels for Radar and Stargate, the levels, caps and waveform as uniforms for Bars and the pillar levels for Orbit, and a new ring or ridge line for Cosmic Peanut and Pulsar when one comes in.

[bink2_poster_test](../../tests/bink2_poster_test.cpp) runs the helper in the real sandbox, as a mode of the test program: without a file it refuses what is not Bink 2, headers that cannot be played and damaged frames, also through the thumbnail call; with one it checks the poster's size, aspect and mean color against the library's own RGB of the first frames and against the decoder run in the test process, and that a cancelled request gives none; [bink2_failure_test](../../tests/bink2_failure_test.cpp) cuts a copy of the file after the element prerolled and expects an error at the element and the player, and holds the element's buffers downstream while stopping; [bink2_sound_test](../../tests/bink2_sound_test.cpp) holds the sound checks; [media_view_seek_test](../../tests/media_view_seek_test.cpp) holds seeks in flight at the frame sink's counting filter and checks that a quick seek shows no note and a slow one shows it after the delay and loses it on settling, on a refused seek, on a newer seek and when the view stops. The [bench](../../tools/bench/bink2_bench.cpp) times decoding, playback with the sink's dropped frames, and the longest exact seek. The suites wait on conditions with deadlines on the steady clock. GStreamer's plugin registry for these suites lives in their private temporary folder.

## Tables

CSV, TSV, XLSX and ODS files are previewed as tables. `startTableLoad` in [table_loader.h](../../src/thumbnails/table_loader.h) picks the path from the content type, then from the name, and hands back a [TableGrid](../../src/formats/table_grid.h) or a sentence fit to show. Its callback runs once on the main context, also after cancellation, and only local files are read.

Delimited text is read with `startUserFileRead` up to 8 MiB, then parsed in a job on a worker: the dialect is detected (TSV always splits at tabs), a header, a row and a column more than the grid holds are read, so the grid tells whether rows or columns were cut, a detected header row becomes the column names and each cell is typed as a number, a date or text. A file cut at the byte limit loses its last row, which the cut may run through; when a read limit stops the parse first, that row lies past the grid's last. Text that holds private key material is refused.

Workbooks are read in the resource-limited helper: `--sheet-preview-worker` in [sheet_preview.cpp](../../src/thumbnails/sheet_preview.cpp), with the workbook as descriptor 3 and its answer on standard output, captured in a memory file of at most 32 MiB. Files over 64 MiB are refused before the helper starts. [zip_members.cpp](../../src/thumbnails/zip_members.cpp) reads each member a sheet reader asks for (the workbook, its relationships, styles, shared strings and the one sheet for XLSX, `content.xml` for ODS) in a pass of its own over the archive, into memory with libarchive, and counts unpacked bytes as they arrive, whatever sizes the archive states: at most 64 MiB per member, 160 MiB in all across the passes and 10,000 members per pass, kept or not. Members no reader asks for, such as pivot caches and the other sheets, are passed over and count toward no byte limit. A repeated member name is an error. The sheet readers then run under their own limits of 5,000 rows, 256 columns and 200,000 cells. The answer is a small versioned binary format, big-endian: `NSR1`, the sheet names, the sheet index, a flag byte (cut, rows cut, columns cut), the first row and column of the used range, the row and column counts, then each non-empty cell as row, column, type and text; or `NSE1` and a short printable message. The parent shows the helper's message only when it is one of its own sentences, that the workbook is too large or the sheet does not exist; any other says the spreadsheet could not be read. The parent checks every count, length, index and cell order against the grid limits before it allocates or stores anything, so a helper that answers with garbage gives an error state, never a large allocation.

A grid is dense: one text buffer, one end offset and one type byte per cell, row after row. It holds at most 10,000 rows, 256 columns, a million cells and 16 MiB of text, and every cell is one line of valid UTF-8 cut at 256 bytes. It records whether the source held more rows, more columns, or more of anything else than it shows. A sheet keeps its own row numbers and column letters, numbers show up to 15 significant digits, booleans read TRUE and FALSE, and dates and times are in ISO form.

[TableView](../../src/ui/controls/table_view.h) shows a grid: a sheet list when the workbook has more than one sheet (the owner reloads by sheet index, and the list stays while a message such as a load error replaces the grid), a notice when the table is cut that names the rows or columns left out, or says that some of the table is not shown, a header row of column names or letters, row numbers, and cells aligned by type, with numbers, dates and times to the right and booleans and errors centered. Column widths come from the header and up to 200 sampled rows, the first 100 and 100 spread to the last, reading at most 256 KiB of cell text shared by the columns, between 3.5 and 22 em, estimated from character advances measured again when the text size, the pixel scale or the fonts change. A new table or message takes effect for clicks at once, so a click that arrives before the next frame selects nothing. Only the cells in view have labels, taken from pools keyed by cell ([table_view_pools.h](../../src/ui/controls/table_view_pools.h)). The cells, the column names, the row numbers and the rules each sit in a layer that moves as one node when the grid scrolls, so a scroll frame measures only the cells that come into view. The owner calls `update()` once per frame and sets the text size; layout only places the layers and arranges labels bound since the last frame. One cell is selected. The arrow keys, Page Up and Page Down, Home and End (with Ctrl, the first and last cell) and a click move it and scroll it into view, and the view reports its row and column in the source. Cells are drawn on SurfaceContainerLow, the header and row numbers on SurfaceContainer, rules in OutlineVariant, and the selected cell in PrimaryContainer with a Primary border.

The [table grid](../../tests/formats_table_grid_test.cpp), [zip members](../../tests/zip_members_test.cpp), [sheet preview](../../tests/sheet_preview_test.cpp), [table loader](../../tests/table_loader_test.cpp) and [table view](../../tests/table_view_test.cpp) suites run headless, with hostile archives and helper answers among their cases. The [table view pixels](../../tests/table_view_pixels_test.cpp) suite draws a CSV, a two-sheet XLSX, its sheet list beside a load error and a cut table offscreen at 1x and 1.5x, and measures loading and scrolling a 5,000-row table.
