# Browsing

## Navigation and search

The location bar shows clickable folder breadcrumbs. Double-click a breadcrumb or unused space in the bar to edit the path; Ctrl+L also starts editing. Tab accepts a path completion when one is available. Home and its descendants use Home as the breadcrumb root; you can still navigate above it.

The mouse's Back and Forward side buttons navigate folder history, like the toolbar arrows or Alt+Left/Alt+Right. Each press navigates once; releasing the button does not navigate again. In split view, pressing a side button over a browsing pane focuses that pane and uses its own history. Over shared chrome, the active pane's history is used. Side buttons do not navigate behind an open dialog or during a captured drag, and do nothing when the corresponding history is empty.

By default, typing while browsing starts a recursive filename search rooted in the current folder. Settings → General → When typing also offers Filter current folder and Select names. Filtering immediately narrows the live folder listing by a literal, case-insensitive name substring, without looking inside subfolders. For example, `temp` matches `Template1.csv`, `Template2.csv` and `Templates` in the current folder, but not files inside `Templates`. Hidden-file and backup-file visibility still apply.

The field next to the location bar shows Search files… for recursive search, or Filter files… in current-folder mode. Clicking it or pressing Ctrl+F uses the same scope. Clear the query or press Escape to return to the folder listing. Select names changes typing to name selection while keeping explicit searches recursive. Content search and an indexing service are not part of the current search.

| Action | Shortcut |
| --- | --- |
| Back / Forward | Alt+Left / Alt+Right |
| Parent folder / Home | Alt+Up or Backspace / Alt+Home |
| Keyboard shortcuts | F1 |
| Edit location / Focus search | Ctrl+L / Ctrl+F |
| Open terminal in current folder | F4 |
| Refresh | F5 |
| Undo / Redo | Ctrl+Z / Ctrl+Shift+Z |
| Show hidden files | Ctrl+H |
| Show sidebar / Show preview | F9 / F8 |

Open Terminal Here is near the top of the folder background menu. A single folder's context menu offers Open in Terminal directly, targeting that folder. F4 always uses the active pane's current folder, regardless of selection; it also works while editing the location/search field, without submitting or clearing its text. Dialogs block the shortcut. Terminal actions require an accessible native folder and use Settings → General → Terminal, then the existing environment/discovery fallback.

### Keyboard navigation

In List and Columns, Right or Enter enters the folder under the cursor and Left or Backspace goes to its parent. Entering a folder from the keyboard selects its first item; going up selects the folder you left. In a List view folder tree, Left and Right still collapse and expand folders first. Grid keeps Left and Right for moving between items. Backspace edits typeahead or the search query while one is active.

The cursor ring marks the item the keyboard acts on and stays visible inside a multi-selection. Ctrl+arrow keys move it without changing the selection, and Ctrl+Space selects or unselects the item under it. Ctrl+Enter opens the folder under the cursor in a new tab; Ctrl+Shift+Enter reverses the Switch to new folder tabs preference. Escape anywhere outside the file list, such as Places or the toolbar, returns focus to the list. In the search field, Down or Enter moves to the results with the first one selected. F1 lists every shortcut.

## Network folders

Enter an address such as `smb://server/share` in the location bar, or open a saved network place. If the location is not mounted, Luciole asks the installed GIO/GVfs provider to connect and then opens the folder. You can also open an SMB server address and activate one of its listed shares. The same mounted share becomes visible to other applications using that desktop session.

When the server requests login, use the username, domain and password fields, or Guest if the server offers anonymous access. A rejected password can produce another login prompt. Cancel stops that connection attempt; refreshing or opening the address again lets you retry. Navigating away or closing the page cancels its pending request. Credentials are passed to GIO for the session and are not saved in Luciole settings or bookmarks.

Network protocols require their installed GVfs backends and a session D-Bus connection. See [packaging requirements](../../PACKAGING.md#gvfs-and-trash). A separate connect-to-server form, device-unlock dialogs and process-blocked mount questions are still planned.

## Views and selection

[Undo/redo](file-operations.md#undo-and-redo) affects the most recent supported creation, rename or native copy/link/move in the running application, independently of the current folder or selection. When a text input is focused, its text-editing undo takes precedence.

Use the toolbar or main menu to choose Grid (Ctrl+1), List (Ctrl+2), Columns (Ctrl+3) or Workbench (Ctrl+4). File picker windows offer Grid and List only. Ctrl+wheel changes grid icon size. View, zoom, sort and hidden-file choices are saved as defaults for new browsing pages. Existing tabs and panes keep their own browsing state.

List and Columns shorten overflowing filenames in the middle by default, keeping their beginning and ending visible. Settings → Views → Long filenames also offers Shorten at the end. Changes apply to open panes immediately. Grid keeps its two-line name wrapping.

List headers sort by their column. Drag their dividers to resize columns; Settings → List columns controls visibility and order. Additional columns include accessed/created time, owner, group, permissions and location. Missing provider metadata stays unavailable rather than becoming a made-up value. Grid view uses the toolbar's Sort menu.

In large folders, names can appear while detail values are still loading. “Reading…” means a value is pending; “Unknown” means it was unavailable after querying. Hidden extra columns are not queried by ordinary large-folder browsing. Enabling one loads its visible rows. Sorting by metadata or selecting many items can require facts from the rest of the folder; file actions wait for the facts they need.

The floating status pill reports actions, search and selection. Settings → Appearance → Always show status bar keeps it visible when idle with the item count and, when available, free space.

Click an entry to select it, Ctrl+click to toggle it and Shift+click to select a range. Clicking empty space clears selection. Drag an area over entries to select several. Ctrl+A selects all visible results, Ctrl+Shift+I inverts selection and Ctrl+S selects by pattern. Escape clears the selection when browsing. Opening uses double-click by default; Settings → General offers single-click opening.

## Places and folder trees

Places contains Home, available XDG user folders, Trash and your pinned folders. Pin or unpin a folder through its context menu, or drag a folder into Places. Drag rows to reorder them. Trash can move within the list but cannot be unpinned. Its context menu offers Empty Trash.

Pinned folders use the shared GTK bookmark file, also used by Nemo and Nautilus. Adding, removing, renaming or reordering user bookmarks in Luciole updates that file; changes from another application appear automatically. Built-in Places keep their Luciole layout and are not automatically added to other applications' bookmarks. Old Luciole-only pins are not imported.

Drives starts with File System (`/`), followed by the volumes and mounts GIO reports: removable media, extra partitions and network mounts, but not other system mounts such as `/home` or `/boot`. Mounted drives come before unmounted ones. In the Places list, each mounted drive shows a bar of its used space under its row; the bar turns red at 90% used. Unmounted drives and filesystems that do not report a size have no bar.

The eject button and the drive's context menu remove a mounted drive the way GNOME Files does: Safely Remove powers off a USB disk plugged in during the session, Eject ejects removable media, and Unmount unmounts anything else. Removal never forces: while a program still has files open on the drive, nothing is unmounted and the status bar names the programs or Luciole's running file operations that keep it busy.

Settings → Appearance controls sidebar visibility, width, drive rows and the optional folder tree. The separate expandable-folder preference adds a tree within List view. Both tree options are off by default.

## Tabs and split view

Each tab can contain one or two browsing panes. A split belongs to its tab; it does not create another tab. Navigation, search, selection and scroll belong to each pane. Actions target the focused pane.

The tab bar is shown by default even with one tab. Settings → Appearance → Always show tab bar can hide it when there is only one tab.

Middle-click a folder, breadcrumb or Places row, or use a folder's Open In → New Tab menu, to open it in another tab. Settings → General → Switch to new folder tabs is on by default. Turn it off to load those folders in background tabs while keeping your current tab, focused pane, search, selection and scroll. Shift+middle-click reverses the preference for that one opening. Click the tab or use Ctrl+Tab to visit it when ready.

Ctrl+T, the plus button and explicit New Tab menu actions always switch to the new tab. Duplicating or reopening a tab also selects it, and New Window retains its normal focus behavior. The folder-tab preference does not change those actions.

| Action | Shortcut |
| --- | --- |
| New tab / New window | Ctrl+T / Ctrl+N |
| Duplicate tab / Reopen closed tab | Ctrl+Shift+D / Ctrl+Shift+T |
| Close tab / Close focused split pane | Ctrl+W / Ctrl+Alt+W |
| Next / Previous tab | Ctrl+Tab / Ctrl+Shift+Tab |
| Toggle split / Switch pane | F3 / F6 |

Enable Restore tabs from last closed window in Settings → General to reopen the last closed window's tabs once in a new window or on startup without a requested location. The saved session is consumed when restored.

## Miller columns

Columns show successive folder levels inside one pane. Selecting one folder reveals its child column. Selecting a different folder replaces the descendant branch. Right or Enter moves into the selected folder's column with its first item selected; Left, Backspace or Alt+Up moves back to the parent column. Each column scrolls vertically, and horizontal scrolling reveals additional levels. Dividers resize columns.

Show parent folders is enabled by default in Settings → Views. Disable it to start Column view at the current folder alone. Deep navigation remains possible, while the application retains only a bounded set of live columns.

## Workbench

Workbench (Ctrl+4) shows the current folder together with what lies below it. The left column holds the instrument above Jump ahead. On the right, the ribbon sits above the center: ancestor strips, the folder's list and up to three quieter columns ahead. Shapes and weight bars are sized by Size by and colored by Color by (Settings → Views → Workbench). Folder sizes are the apparent sizes of the files below them, measured in the background; a folder whose size is still being measured, or whose measure was cut short (it lies too deep or above the measured folder, the walk reached its limits, it is on another drive, or it cannot be read), is drawn hatched. While it is being measured its size and count read "measuring…" until they are known. A folder whose measure was cut short and is not running reads "not measured", or "at least" followed by what was counted, and stays that way until you open it. A folder on another drive or one that cannot be read reads "not measured", and every folder above it reads "at least" while it is not counted; opening it measures it in full when it can be read.

The list is the same one List view shows. Its header and sorting, typeahead, rename, drag and drop, context menus, the status bar and every action work on it as they do in List view, and selection always belongs to the list. It shows the columns chosen for List view that fit its width whole and never scrolls sideways: when room runs out, columns beyond Modified leave first, then Type, Modified and Size, and Name takes the room that is left. Its columns are not resized in Workbench, and the columns and widths chosen for List view stay as they are, so a wider list shows them again. In the columns menu, a chosen column that does not fit shows as checked and unavailable, with "(does not fit)" after its name. The status pill sits in the list's bottom corner, below the list's rows, so it never covers the row under the cursor, and it stays inside the list: when the list has no room for both, free space leaves first, and a status too long for the pill ends in an ellipsis. Back, Forward and Parent folder step through the folders you entered from any pane, and Workbench stays on while you do. When the folder changes, the strips, the list and the columns ahead slide and fade into their new places in about a quarter of a second, coming from the columns' side when you go deeper and from the strips' side when you go up.

- **Instrument:** Nest (nested rectangles), Iris (rings) or Atlas (packed circles). Click a folder to enter it, or a file to move the list's cursor to it. In Nest and Iris the wheel steps between levels; in Atlas it zooms, and zooming into a folder enters it. While the instrument has focus, the arrow keys, Home and End move between pieces, Enter enters a folder or opens a file, and Backspace goes to the parent folder. Atlas also zooms with + and - or Page Up and Page Down. The wheel, the keys and the zoom buttons ease the zoom over a few frames, and 0 or the recenter button returns to the whole folder. Drag to pan the Atlas; a click on empty space goes up one level. Chips at its top left, or in the bar above a small Atlas, go to an ancestor folder, and resting on one shows its path. Entering a folder nearby flies to it; a jump farther away cross-fades. In Nest, resting the pointer on a folder's tile for about a third of a second, or pressing Space on it, opens a card showing that folder's own entries; while a card opened by Space is open, the arrow keys walk its tiles, Enter opens the one walked to and Space closes it. Turning the wheel up over a folder in the card enters that folder. Moving off the card, a click or another key closes it. A "+N more" piece stands for the entries too small to draw. In Nest an entry is folded only when its tile could not hold a name at the smallest label size, so the lightest fold first and small files beside large ones keep their tiles while the pane has room. Clicking it lists the 100 heaviest near the pointer with their Size by values, followed by a count of any others, and choosing one does what clicking its piece would. In Nest and Iris it is also a keyboard stop, where Enter shows the same list beside the piece. In Iris the names of the folders above sit over the rings, each going up to its folder when clicked, and the hub shows the folder's size and item count; after you go up, chips in the hub lead back down the way you came, the same way the columns ahead reopen, whichever instrument was showing. The hub's note on a folder with nothing to show, such as "This folder is empty", wraps inside the hub, keeps clear of its border and gets smaller only where wrapping alone would leave it; where it still does not fit, the item count gives way to it and then its last lines end in an ellipsis. A size or a count in the hub is shown whole or left out, the hub shortens "at least" to "≥" in a size where space is tight, and the hub's name is cut in the middle. Pointing at a folder's piece shows its own entries along the ring's inner edge, and in a small pane a line at the bottom names what the pointer or the cursor is on, with its size and count whole at the right end.
- **Tooltips:** Resting on a piece of the Nest, Iris, Atlas, Flame, Flow or Ladder shows its name and facts: size, item and file counts or type, when it changed and how often it was opened, and in every view but the Nest its share of the folder. The Iris shows name, size and share as a table while every amount is exact, and the same text as the other views when one reads "at least", since a table row holds one line. When a folder's entries are not listed in the snapshot, the tooltip says "not expanded".
- **Why an amount reads "at least":** Resting on an amount that reads "at least" or "not measured" says why, wherever it is printed: a piece, the hub's total, a "+N more" tile of the Nest or the Flow, a row of Jump ahead, or the status bar's selection size. The reason names the folders that were not counted, at most three and then "and N more": "Not counted: proc, sys and dev are on another filesystem." or "Not counted: 2 unreadable folders (cache, lost+found)." Where the snapshot cannot tell which folder, or has more of them than it reads for one tooltip, it says "Not counted: some folders below were not counted in full." A folder above the open one is measured only up to a limit, so its tooltip says that and names no folder: "Not counted: measuring this folder stopped at a limit, at another filesystem or at a folder that cannot be read." It shows no share either. An amount that is exact has no such tooltip, and neither does one that reads "measuring…". The list a "+N more" piece opens does not give it.
- **Jump ahead:** folders two or more levels below the current one, the most visited first, then the largest, each with its path and its Size by value. A row opens its folder with a click or a double-click, following Settings → General → Open items. Up, Down, Home, End and the page keys move through the rows, and Enter or Space opens one.
- **Ribbon:** the flame graph, the flow diagram or the ladder of the levels above. Clicking a folder enters it and clicking a file moves the cursor to it. In the flow diagram a bar's label counts as its bar, and the bands between the columns take no clicks. An ancestor pill of the flow diagram shows its name or is left out. A fact is told once: under Size by Items a folder's item count is not repeated beside its size. Its "+N more" pieces list what they stand for, as in the instrument; in the flame graph and the flow diagram that is folders only.
- **Ancestor strips:** a pane of narrow bands beside the list, one per folder above the current one, each with the folder's name. The nearest sits beside the list and the bands thin with distance. The pane shows as many bands as its width holds, at least one, and folds the folders beyond them into one "+N levels" band at the far side, which goes to the nearest folder it holds. Bands keep their widths: a pane wider than its bands leaves the rest empty, and the pane keeps its width when you go up or down, so the list does not move sideways. By default the pane holds four bands and the "+N levels" band; drag its divider on the list's side to show from one to twelve, or all thirteen when no folder is left to fold. A click, Enter or Space goes up to that folder. After Enter or Space the keyboard focus stays on the strip nearest the list, or moves to the list when no strip is left. Settings → Views → Workbench → Ancestor strips turns them off, and the list then starts at the center's edge.
- **Columns ahead:** the folder under the list's cursor; when the cursor is on none, the folder you last entered below the current one, else the heaviest; then, inside each column, the folder you last entered there, else the heaviest. Each tab and pane remembers, while it stays open, the last folder entered below each folder. Columns use smaller text than the list. When the pointer rests on a row of the list or of a column, the columns follow that row instead, and they return to the cursor shortly after the pointer leaves. With double-click opening, a click on a column row pins it, so the columns keep following it; a double-click opens it. With single-click opening, a click opens it. The pin button in a column's header holds what follows that column until you press it again, move the cursor or change folder. When the folder has no subfolders and the cursor is on no file, the first column says "No folders ahead" and the others stay empty, drawing nothing.

Pointing at an entry in any pane marks it in the others: the instrument and the ribbon highlight it, Jump ahead and the strips mark it, and the list marks the row of the current folder that holds it. Middle-click a folder in the instrument, the ribbon, Jump ahead, a column ahead or a strip to open it in a new tab; Shift reverses Switch to new folder tabs, as elsewhere. Right-clicking an entry of the current folder opens the list's context menu for it; other entries offer Open, and Open in New Tab for folders.

When the cursor or a resting pointer is on a file, the columns stop there and the next column slot shows its preview, taking the room up to the right edge, in the column's smaller text. Its header names the file and its type, a model the viewer can read being named a 3D model whatever the system's type database calls it, with the size controls and an Open button, and a line of facts gives its size and date and, where known, its lines, rows and columns, a picture's pixel size, archive entries, playing time or triangles. A text longer than 256 KiB shows its first 256 KiB and a table its first 10,000 rows; their facts then leave out the line or row count. The content fills the rest:

- Text, code, JSON, YAML, TOML, INI, XML, diffs and Markdown show as colored text, Markdown with its headings, lists, quotes and code blocks, and each color code with a swatch of its color. Prose wraps at word boundaries to the column's width, a word longer than the column breaking inside itself, and wraps again when the column or the preview size changes. Plain text written to be read, such as .txt files, README, LICENSE and CHANGELOG, is prose; a line of more than 1,024 characters goes on in a new row after its first 1,024. Code, logs and other text laid out in columns keep their lines and scroll sideways. A scrollbar shows only when some of the text is out of sight. Hovering a swatch shows its value.
- CSV, TSV, XLSX and ODS show as a table. A workbook lists its sheets above the table; choosing one shows it. A cell is selected, and the arrow keys, Page Up, Page Down, Home and End move it while the table has focus.
- Pictures show fitted to the column and never larger than their own pixels; an SVG fills the column. An animated GIF, PNG, APNG or WebP plays; a click pauses and resumes it.
- Video and audio play when Luciole is built with playback: the usual still stands as the poster until you press Play, with a position bar, the elapsed and total time and Mute. A click on the picture plays or pauses, the poster before the first Play included, and gives it the keyboard; Space then plays and pauses again, and Left and Right step five seconds. A click on any control of the bar, such as Play, the position bar, loop or Mute, gives it the keyboard the same way; Tab still reaches the buttons, and Enter or Space then presses the one focused. A sound file that cannot play, such as one on a machine with no sound device, shows the reason in the middle of the preview where its glyph was, and the controls are as they were before Play. Without playback they show as stills. While a sound file plays, and while it is paused after playing, a visual that moves with the sound takes the place of its cover or sound glyph: Cosmic Peanut, Pulsar, Bars, Orbit, Halo, Radar, Eclipse, Dark Sun or Stargate. Two buttons beside Mute turn the visualizer off and on and step to the next visual, or with Shift to the previous one; the visual button's tooltip names the visual shown. Settings → Views → Workbench offers the same choice as Audio visualizer and Visual, and a change in either place applies to a playing file at once. Muting or turning the sound down leaves the visual as it is. Turned on while a file plays, the visual follows the sound after about a second and a half. Video always shows its own picture. Bink 2 video, the format of some games' movies in `.bik` and `.bk2` files, plays the same way with its own sound, also tracks that run ahead of the picture; its picture is decoded by Luciole itself, so it needs nothing installed. Seeking to a time in the middle of a long stretch between key frames takes as long as decoding that stretch, up to several seconds in a 4K file and over twenty in a clip whose last key frame is far from its end, and a newer seek or closing the preview cuts it short; the picture stays where it was until the seek is done. Its still before Play, and its thumbnail in lists, is a picture from the first half second of the clip made by Luciole itself, in a separate process like other thumbnails: the first frame that is not black, or the brightest of the first 30 when all are. A seek that takes longer than about a third of a second, which happens in clips with few key frames, shows "Seeking..." beside the time until it is done, in every video and sound file; the older Bink 1 format does not play. Only pictures up to 4096 pixels on a side play. A loop button beside Mute, for video and sound alike, makes a file that reaches its end start again from the beginning and keep playing; the button shows whether loop is on, a click applies at once to a file that plays, and the choice is remembered for every file and across restarts. A very narrow column hides the elapsed and total time to leave room for the position bar and the buttons, and for a sound file in the narrowest column the visual button as well; both come back when the column is wider.
- STL, OBJ, PLY, glTF and GLB models show lit in 3D. Drag to turn the model, use the wheel to zoom, and the button in the corner returns to the first view.
- An archive lists the entries it holds with their sizes, folders ending in "/"; its entry count counts the same entries. A folder that appears only in the paths of other entries is not listed. An archive of more than 50,000 entries, or past another of the reader's limits, is not listed and says it is too large to list.
- A file of unknown type shows its text when it reads as text, else its bytes in hex, up to the first 64 KiB. A hex row holds 16, 12 or 8 bytes, the most whose rows fit the column's width, and the rows change shortly after the column is resized, keeping the same bytes in view.

Settings → Views → Workbench → Preview placement decides where the preview is shown. Replace Jump ahead when it does not fit, the default, keeps it in its column and, when the window or the output scale leaves no column with room for it, shows it in the Jump ahead pane under the header "Preview". Always replace Jump ahead shows it in the Jump ahead pane at every window size; the columns are laid out as usual, and the one a preview would have filled stays empty, so the list does not change size as the cursor moves between files and folders. Hide when it does not fit keeps it in its column and shows none when no column has room. The pane shows the preview only while a file is the preview's target; with no such file, such as a folder under the cursor or nothing selected, Jump ahead stays. The preview there is the same as in a column, with the media controls, editing, the size controls and the Open button, and it follows the same targets, so a pinned file or a resting pointer picks it too. With Jump ahead collapsed, closed because the window is too small, or covered by the expanded instrument, no preview is shown under the first and third choices when no column has room, and none under the second at any size. A change of the setting, or of the window's size, applies at once and a preview being edited keeps its text.

A file the preview cannot show says why in a sentence in place of its content, such as "This spreadsheet is too large to preview." or "This file is damaged or is not an STL model."

The size controls in the header, beside Open, make the content smaller or larger in steps of 70, 80, 90, 100, 110, 125, 150, 175, 200, 250 and 300 percent; the step between them, 100% at first, returns to 100% when pressed, and Ctrl with the wheel over the content steps the same way. One size, saved, applies to every preview in every tab. Text, tables with their headers and sheet list, archive listings and the hex view change their text size, keeping the same line or cell at the top (a wrapped paragraph is one line, and the top stays the same fraction of its height into it, also when the column's width changes); at 100% their text is one size below the list's. Pictures and animations grow or shrink from their fitted size, keeping the same point in the middle, and a picture larger than the column scrolls with the wheel and moves when dragged. A 3D model's camera moves nearer or farther. The header's own text and the rows of the columns ahead keep their size. In a narrow column the header's parts do not overlap or get cut: the file's name is shortened in the middle in the room it has, the size controls move to a line of their own, and then Open does too; Open stays whole. Video and sound stay fitted to the column, and the side pane's preview over the slot keeps its own size: there the controls are disabled and their tooltip says why.

PDF pages, fonts, documents, a picture that cannot be read and every other kind show what the side pane would show below the header: the page, sheet, picture or type icon and the details the header leaves out, in the column's smaller text. Moving the cursor across files loads only the one it stops on, a quarter of a second later; a file the pointer rested on, or a pinned one, loads at once. A slow file says it is loading while everything else keeps working. A tab in the background holds no preview and plays nothing; its file loads again when the tab returns. A file holding private key material shows a notice instead of its text. The side preview is not shown in Workbench: F8 does nothing there, and the menu's Show preview item is unavailable. Space still opens the quick preview of the selected item.

### Editing

A file the column preview shows as text has an Enable editing button under its header. Pressing it reads the whole file again and puts an editor in place of the text, with the keyboard in it: the file's own lines, colored as source, Markdown and JSON as written, at the preview's text size. Ctrl+Z undoes, Ctrl+Y or Ctrl+Shift+Z redoes, Ctrl+C, Ctrl+X and Ctrl+V use the clipboard, and Tab and Shift+Tab indent and outdent. The button is disabled, its tooltip saying why, when the file is larger than 1 MiB, has a line longer than 16 KiB, holds a private key, is read-only, lies in a read-only folder, or has other hard links. A file the preview shows as hex, because it is not UTF-8 text, has no button.

A CSV or TSV file the column preview shows as a table has the same button, for the same reasons. Editing makes the table editable, with a bar of buttons above the grid: insert a row below the selected cell, delete its row, insert a column to its right, delete its column, undo and redo. Enter, F2, a double click or typing opens a field over the selected cell; Enter and Tab commit it and move down or right, Shift+Tab moves left, Escape cancels, and Delete or Backspace empties the cell. Ctrl+Z undoes, Ctrl+Y or Ctrl+Shift+Z redoes, and text left in the field counts as a change once you save or leave. The names in the header row are not edited here. The button is also disabled when the table has more rows or columns than the preview shows, or a quote that is never closed. XLSX and ODS spreadsheets are read-only here. A change that would make the file larger than 1 MiB, or give the table more rows or columns than the preview shows, is refused, and the bar says why. A save rewrites only the cells, rows and columns you changed: the rest of the file, its quoting, line endings and byte order mark stay as they were.

While a file is edited, the bar under the header shows Save, Stop editing and, while some changes are not written, "Unsaved changes". "Unsaved changes" moves under the buttons when it does not fit beside them. Its place is kept for as long as the file is edited, so nothing below the header moves when it appears or goes. The facts line below the file's name (its lines, or rows and columns) describes the file as last saved. Only Save writes: the button, or Ctrl+S in the editor or the table. A save keeps the file's line endings, byte order mark, final newline or its absence, permissions, owner and extended attributes, and a file that was not changed is never written. A text file that mixes line endings says so when editing starts, and a save writes its most common ending throughout; a table keeps each line's own ending without a notice. When a save is refused, because the folder is read-only or the file changed on disk since it was read for example, the bar says why and the text stays as it is. The bar also says when the file changes on disk while it is edited.

While a file is edited, the editor and a table's cell field keep the keys that edit, and a click on the header, its size buttons, the bar or the space between them leaves the keyboard where it was. The view shortcuts (Ctrl+1 to Ctrl+4) and Alt+Left, Alt+Right, Alt+Up and Alt+Home leave the file like the toolbar and the breadcrumbs do. While a file is edited, a resting pointer does not move the columns; a click, a key, another folder, another view mode or expanding the instrument does. A window too narrow to show the column keeps the editor, out of sight, until the column shows again. Leaving unsaved changes asks one question, "Save changes to <name>?": Save writes and then moves on, and No drops the changes. A view change (Ctrl+1 to Ctrl+4, the toolbar or the menu) asks first, with the editor still shown, and switches once you answer, with the file selected in the new view. The question takes the keyboard and the pointer, so another view cannot be asked for until it is answered. Changing the default view in Settings switches the view first and asks afterward. Escape and the dialog's close button mean No, and a click beside the dialog does nothing. The editor stays until the answer, and the preview then shows where you went, however many times that changed meanwhile. A save that fails keeps the question open with the reason. Stop editing, and Escape in the editor or on the table's grid, ask the same question and return to the file, read-only. Closing the tab, the pane or the window, and quitting, ask first. Switching to another tab asks nothing: the editor keeps its text and place, and a question that was open is asked again when you return.

Every pane but the center has a 24 px header with its name. A header too narrow for its whole title first leaves out why the view closed the pane, then the kind it shows, and its tooltip gives the whole title. The instrument and ribbon headers switch between kinds; the choice is saved as the Instrument and Ribbon settings. The header buttons collapse a pane to its header and restore it; with both left panes collapsed, the left column becomes a narrow rail with a button for each. Expand covers the whole view with the instrument; Return in its header, or Escape, brings the other panes back, already showing any folder you entered meanwhile; while you edit the address or the filter, Escape first ends the edit. Reset layout, in the ribbon's header and in the expanded instrument's, restores every size, collapsed pane and column width, the ancestor strips pane's included.

Drag the dividers between panes, the left edge of a column ahead, or the ancestor strips pane's edge beside the list, to resize. Focused dividers move with the arrow keys; Home or a double-click restores the default. Arrow keys on the strips pane's divider step its saved width, also while the window draws the pane narrower. Escape during a drag puts the pane back. Sizes are saved when you let go, and each ribbon kind keeps its own height. The list never gets narrower than 320 px while the ancestor strips pane can give up room: when there is no room, columns ahead drop from the right, then the strips pane is drawn narrower, down to its one band and the "+N levels" band, without changing its saved width; a small window or a narrow split pane closes the ribbon first, then Jump ahead, then turns the left column into the rail.

## Preview and Properties

The side preview is on by default. Resize its divider to change the saved width; small windows temporarily collapse it when there is insufficient room. F8 toggles it, and Space opens a quick preview for one selected item. In the quick preview, the arrow keys move the selection as in the view behind it: Left and Right step one item, Up and Down one list item or one grid row. Space or Escape closes it. Images, video stills, the first PDF page and embedded audio artwork depend on installed providers. Video previews are still images, not playback. A TrueType, OpenType, collection, WOFF or WOFF2 font shows its family and style and a sample at several sizes drawn with its own glyphs, in a script the font covers; symbol and icon fonts show a grid of their glyphs. Its details list the version, format, glyph count, faces, variable axes, whether it is monospaced or has color glyphs, and the scripts it covers. WOFF2 fonts need a FreeType built with WOFF2 support. Font previews follow the Image/PDF size limit, up to 256 MiB. Previewing a font does not install it.

The preview shows essential content facts such as file size, dimensions, format and duration when available. Properties (Alt+Return) includes additional technical and permission information. Properties and file-operation dialogs stay open when you switch windows; use their buttons or Escape to close them. See [file operations](file-operations.md#properties-and-permissions).

File types use the system MIME database and GIO content detection when the name alone is insufficient. For example, a text `.bash_history` can show as Plain text document with MIME `text/plain`; an unrecognized binary stays a generic file. The detected type is shared by the list, preview and Properties. Readable local UTF-8 text formats, including YAML and desktop-entry contents, support text previews. Desktop entries also show their localized application or link name and description in preview and Properties. When the part of a file that the preview reads contains private key material, such as an SSH, PEM, PGP, PuTTY, age or WireGuard key, the preview shows a notice instead of the file's text.

## Background operations

The toolbar's File Operations button shows the number of active jobs. Open it, or use File operations in the main menu, for progress and recent results across the running application's tabs and windows. See [file operations](file-operations.md#file-operations-popover) for cancellation, reports and retry behavior.
